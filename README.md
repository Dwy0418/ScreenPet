# screen-pet · 屏幕边上的陪伴 AI

一个住在屏幕空白处的桌面挂件：它会**每隔几秒看一眼你正在看的视频**（整屏 / 框选一块 / 只盯某个程序都行），
先在脑子里过一遍 Who / What / When / Where / Why 把画面看准，再用一句气泡冒出
**像朋友随口说的话**（吐槽）。想聊两句就打字或者直接说话。形象、性格、接口全都可以换。

```
┌──────────────┬───────────────────────────┬─────────┐
│              │                           │  ╭────╮  │
│              │       你正在看的视频        │  │黄豆│  │  ← 它待在屏幕边上的空白处
│              │                           │  ╰────╯  │
│              │                           │ "这操作" │  ← 吐槽气泡（点击穿透，不挡鼠标）
└──────────────┴───────────────────────────┴─────────┘
```

## 它怎么工作的

```
每 2.5 秒截一帧「观看区域」→ dHash 指纹比对（画面没变就跳过）
        ↓ 变了才继续
[① 弹幕/字幕] 本地 OCR 认字（Windows 自带引擎，图片不出本机）
[② 上下文]   取前台窗口标题 + [③ 长期记忆] 翻出观众画像和常看标签
        ↓
缩放成 720px 宽的 JPEG → 发给视觉大模型（人设 + 上面这些线索 + 最近几句吐槽 + 上一眼看明白的场景）
        ↓
返回两行：「[情绪] 一句话」+「场景：人物=…｜事件=…｜时间=…｜地点=…｜原因=…」
        （不想说话就在第一行写 [沉默]；第二行照样要有——两行永远都在，只交场景行不算回答）
        ↓
第一行 → ④ 表情状态机切表情 + 气泡冒出来
第二行 → 存进记忆（打标签、生成画像都用得上），下一轮再喂回去，避免车轱辘话
        ↓
这句话写回本地记忆（关键词自动打标签，攒够了让模型总结一次"观众画像"）
每一句还私下分个类（记录 / 分析 / 学习，见 ③）：只决定怎么记、怎么分析、这一轮怎么接话，不上界面
        ↓
⑤ 同时盯着计时器：画面久未变化 / 自己久未开口（先翻记忆挑个话头）/ 你走开又回来 / 夜深了 → 没人给槽点时自己找句话说
        ↓
⑥ 你打字或者说话时优先回你（不等冷却、连"暂停"都照答）：文字走聊天面板，语音走系统自带识别引擎
        ↓
   要"只盯着一个程序"时：锁定那个进程，之后每帧只拍它窗口的内容区（窗口挪了也跟得上；你切去干别的、它被盖住了，照样看得到）
```

所以它**不是**在分析视频流，而是像人一样"偶尔抬头看一眼"，顺手听听旁边在聊什么。这样延迟、
成本、隐私都可控，也不需要任何视频解码。

有一点容易误会：**它不说话，绝大多数时候不是坏了，是它选了沉默**。所以输出格式里把"沉默"
也规定死了——第一行写 `[沉默]`，第二行（场景）降级成"想起来就写、可有可无"。
为什么这么改：小模型看到"必须交两行"时，一决定沉默就拿第二行交差（日志里一片
「模型只回了场景没给台词」，屏幕上看着就像它哑了）；把 5W1H 原文整段回喂也没用——
它会原样抄回来当第二行（**上一支视频的场景**，画面早换了）。所以现在：场景只回一句
"这一幕你说过了"的提醒、不回喂事实，换视频时还会把它清空。
更隐蔽的一次是**连格式块里的"例句"都照抄**：抄例句当台词（被噪音闸丢成静音）、
抄示例场景当自己的场景（屏幕上明明是《英雄联盟》，它报的是"抽卡直播间"）。所以格式块
现在只给骨架，一句能直接抄的成品都不留。
同一种病还有一个出口：**【你刚才说过】里自己的原话也会被抄**（日志：
`[noise] 模型把提示词抄回来了，这句丢掉：[开心] 这球才15？ / 就这？`——抄的正是这一块），
抄回来的照样被噪音闸丢掉，看着就是"它一直不说话"。现在这一块明说了"这些字是给你避开的、
不是台词，一个字都别再写"，并给出合法出口：想不出新角度就交 `[沉默]`。
真碰上"白看"的那一轮（只交场景行、或者把画面上的字原样抄了回来），只要它已经安静超过
`capture.insist_after_quiet_sec`（默认 30 秒）、而且这段时间还没补说过，它会**再要一次**——
这次换成**单行模式**：系统提示词和这一轮的要求都改成"只回一句话，不要写场景行"，
把"沉默=交场景行"这条路直接堵死。这是整个项目里**唯一**一处会多发一次请求的地方，
调成 `0` 就关掉补说（宁可它沉默也不多花钱）。

## 十个能力

**① 会看弹幕和字幕（本地 OCR）**

默认用 **Windows 自带的 OCR 引擎**（`Windows.Media.Ocr`），零安装、完全离线、图片不上传，
读到文字后交给模型当"大家在聊什么"的素材。装了 `rapidocr-onnxruntime` 会自动优先用它
（不用起 PowerShell 进程，更快）：

```bat
python -m pip install rapidocr-onnxruntime   :: 可选，不装也能用
```

想要的文字块一般就是弹幕/字幕区，把「观看区域」框住那一块识别最准。
识别结果按画面指纹缓存，同一帧不重复识别；连续失败两次会自动关掉自己，不刷屏。

**② 表情状态机（5 种情绪）**

提示词要求模型在句首带一个情绪标签：`[开心] [无语] [激动] [吐槽] [好奇]`，
模型忘了带就按关键词兜底猜一个。情绪会同时驱动：

| 情绪 | 表情 | 动作 | 气泡边框/主题色 |
| --- | --- | --- | --- |
| 开心 | 弯月眼 + 大笑嘴 | 轻快弹跳 | 黄 |
| 无语 | 横线眼 + 直线嘴 | 慢吞吞地歪头、身体发灰 | 灰蓝 |
| 激动 | 眼睛放大 + 圆嘴 | 快速上下跳 | 粉 |
| 好奇 | 瞳孔偏一侧 + o 嘴 | 歪头 | 绿 |
| 吐槽 | 一只眼半闭（挑眉） + 坏笑 | 轻微晃动 | 青 |

> **情绪标签不上界面**。它只在内部用：切表情、定气泡边框色。
> 气泡里**不再画**「好奇」那种小胶囊，聊天面板里也不写 `[开心] 台词`——
> 那个标签本来是给程序看的中间结果，摆在脸上既像调试信息，也像在给你贴标签。
> 同理，每句话私下分的「记录 / 分析 / 学习」也**只走日志和提示词**（见下面 ③）。
>
> **语音播报（TTS）已经撤掉**：以前这里还跟着一句"语速也随情绪变"，现在它只用气泡说话。
> 因此 `pet/tts.py`、`tts.*` 这几个配置项、托盘里的「我先闭嘴」和 `Ctrl + Alt + M`
> 静音热键都一并删了；**语音输入（你说话它听）照旧保留**，那是另一条路（见下面 ⑥）。

**③ 长期记忆（本地 memory.json）**

- **不花钱的部分**：每句吐槽 + 弹幕文字 + 窗口标题都会过一遍本地关键词词典，
  自动打标签（游戏/抽卡/短视频/音乐/学习/宠物……）并计数。
- **私下分类的部分**：每句话还会被分成 **记录 / 分析 / 学习** 三类（`pet/dialog.py`：
  本地关键词 + 情绪兜底，不联网、不花钱）。这个分类**不上界面**，只干三件事：

  | 类型 | 是些什么话 | 它拿去干嘛 |
  | --- | --- | --- |
  | 记录 | 你在交代事情、说自己在干嘛 | 原样进长期记忆和看片笔记；回话时别复述你的原话 |
  | 分析 | 你在评价、吐槽、带情绪 | 记情绪、进口味统计；回话时先跟着你的情绪走 |
  | 学习 | 你在提问、碰到没见过的东西 | 先把知道的答清楚（不知道就直说、别编）；这句算"要补的功课" |

  怎么用起来的：① 它自己说出口的每一句都带着类型存进 `memory.json`（`dialog` 字段），
  攒够样本后提示词里会多一句提醒（例如"他最近问得多：先把知道的答清楚，别编"）；
  ② 你直接跟它说的那句**当场**分类，只留在内存和控制台
  （`[dialog] 他这句是「学习」｜记录 0 / 分析 1 / 学习 0`），换来的是一句更对路的接话提醒
  （问句就先给答案、带情绪就先共鸣），**不落盘**（对话本来就不写进记忆）。
- **花一点点钱的部分**：每攒够 `summary_every_n` 句（默认 25）或过了 `summary_every_sec`
  （默认半小时），让模型把最近的记录总结成 2~3 句"观众画像"。
- 画像 + 常看标签会作为背景塞进提示词，它才说得出"你最近怎么老在看这个"这种熟人话。
- **完整存档：一条都不会丢**。`memory.json` 只留最近 `max_entries` 条（默认 200，给模型看的
  那一份，别越拖越慢），同一时刻还在往 `data/memory/archive.jsonl` 追加一本**只增不减**的
  流水（一行一条 JSON，见 `pet/memarchive.py`）：裁剪、被杀进程、一键清空记忆**都不动它**。
  右键「打开完整存档（一条都不丢）」直接翻；也可以 `python -m pet.memarchive` 看汇总
  （多少条 / 从哪天到哪天 / 常看什么），`python -m pet.memarchive tail 20` 看最近 20 条。
- 全部存在本机（`memory.json` + `data/memory/`），右键菜单里能打开看、也能一键清空
  ——清空清的是"它脑子里那一份"（从此想不起你来过），完整存档照旧留着。

**④ 全部用鼠标（没有全局热键）**

以前这一节是一张热键表（`Ctrl+Alt+R/P/S/T/V/L` 六个组合键）。**现在整套热键撤了**，
理由很直白：热键是"知道才用得上"的东西，桌宠该有的样子是**右键就能玩**；
那几件事全回到了右键菜单里，顺带省掉"热键被别的软件占用"那一类麻烦。

| 想干什么 | 在哪儿点 |
| --- | --- |
| 看什么 + 看哪儿（**合成一节**） | 右键 →「陪你看」→ 先歇会儿 / 接着看、手动划观看范围（拖一块 = 只看这块；双击 / 按 F = 整块屏）、只盯着一个程序 |
| 打字跟它聊 | 右键 →「跟我说说话」→「打字跟我唠…」（**只开不收**） |
| 说一句（语音，离线识别） | 右键 →「跟我说说话」→「说一句（语音）」，跟面板上的「麦克风」同源 |
| 逗它玩（招呼 / 喂一口 / 夸夸 / 摸鱼 / 伸个懒腰 / 戳一下 / 蹦一个 / 点头 / 摇头 / 疑惑） | **左键点它一下**：从动作池里随机演一个（见「动作」那一节） |
| 把我钉在这儿 / 松开（鼠标穿透） | 右键 →「我自己的事」→ 第一项（钉上之后鼠标压到它身上会临时解锁，所以随时点得回来） |
| 鼠标停在它身上（默认 0.9 秒） | 它转过来跟你**挥手**（挥过一次要歇 25 秒；睡着 / 正演着别的 / 正被拖着时不挥） |
| 拖起来再放下 | 落地**蹦一下** |

**点一下 = 逗它一下**（不再弹输入框）：左键点它一下，就从动作池里随机演一个——
池子在 `pet/states.py` 的 `CLICK_ACTIONS`（挥手 / 打招呼 / 欢呼 / 点头 / 摇头 / 疑惑 /
被戳惊跳 / 蹦一个 / 喂一口 / 摸鱼 / 伸个懒腰），挑哪个由 `window.PetWindow._on_click` 说了算，
同一个动作不会连着演两次。想打字聊天走右键「打字跟我唠…」，不用再点挂件了。

**⑤ 主动搭话（没槽点也自己找话）**

只被动等槽点的话，画面一静下来、或者模型一直选择沉默，它就能安静半小时。
所以它还会自己找话说：六种由头、两种代价。

这一套**默认就是开着的**，菜单里不再有开关（以前那个勾选项撤了）——桌宠该有的样子是
抬头就能跟你搭句话，不必先去设置里把它打开。真嫌它吵，配置里写 `proactive.enabled = false`
（命令行 `--no-proactive` 同源）。

| 由头 | 触发条件 | 代价 |
| --- | --- | --- |
| 画面静止 | 连续 150 秒画面没变化，而你人还在 | 调一次模型（让它就着这一帧自己找话题） |
| 久未开口 | 它自己连续 300 秒没说过话 | 调一次模型 |
| **记忆话头** | 同上，但它"憋不住"时先翻长期记忆，拿"你最近老在看的东西"开口 | 调一次模型（素材多一份记忆） |
| **深夜劝睡** | 深夜时段（默认 23:00~06:00）+ 你还在看 + 它已经安静够了 300 秒 | 免费：本地台词劝你睡觉，每小时最多唠叨一次 |
| 你走开了 | 键鼠 420 秒没动 **且** 画面也没动 | 免费：说句"我先眯一会儿"，然后彻底闭嘴 |
| 你回来了 | 上面那种状态里键鼠又动了 | 免费："哟，回来了？" |

"走开"必须**键鼠空闲 + 画面静止**同时成立——躺着看两小时电影手不碰键鼠、
但画面一直在动，它不会把你误判成离开了。

**两条进阶由头**（都能在 `proactive` 里单独关掉）：

- **记忆话头**（`topic_from_memory`）：沉默够久时，它会先去翻 `memory.json`，
  挑一个"你最近老在看、而且见过至少 `topic_min_count`（默认 3）次"的词当话头，
  于是说出口的是"你那个王者荣耀还打呢？"，而不是"你怎么一声不吭"。具体作品
  （比如「王者荣耀」）会排在泛泛的大类（比如「游戏」）前面，最近刚聊过的那个不会连着说。
  注意**记忆只读**：主动搭话永远不写进 `memory.json`，它不会拿自己的碎碎念当你的偏好。
- **深夜劝睡**（`time_aware`）：`night_start_hour` ~ `night_end_hour`（默认 23 点到 6 点，
  跨零点也认）之间，只要它还盯着亮着的屏幕、并且已经安静够了，就先唠叨一句
  "都这个点了，你不睡我可要睡了"。这句优先于其他由头（这个点说"该睡了"比说"你该干什么"合适），
  走自己的冷却 `night_cooldown_sec`（默认 1 小时），免得整晚听同一句数落；
  本地台词，不花钱，提示词里也会带上"现在是凌晨 1:20"这样的时间。

兜底很硬：万一模型还是不肯开口，就用本地台词顶上，所以断网、没配 Key 时
那两句免费的一样说得出来。主动搭话**不写进长期记忆**（免得它拿自己的碎碎念当你的偏好）。

**⑥ 打字 / 语音，跟它实时聊两句**

光看它吐槽有时候你也想插一句。两个入口通向同一个聊天面板（挂在挂件旁边，Esc 收起），
**全都在鼠标上**（热键已经整套撤掉了）：

| 入口 | 怎么用 | 代价 |
| --- | --- | --- |
| 打字 | 右键 →「跟我说说话」→「打字跟我唠…」（**只开不收**，收起来按 Esc） | 调一次模型 |
| 说话 | 右键 →「说一句（语音）」，或面板上的「麦克风」按钮 | 调一次模型（识别本身免费、离线） |

> 点一下挂件**不再**弹这个面板了——那是「逗它一下」（随机演个动作）。

- 你说话时它**优先回你**：不等画面变化、不等冷却，连「暂停」状态都照答。
- 回答会带上下文：当前画面（含你框选的那块区域的截图）、弹幕/字幕、窗口标题、长期记忆、
  以及**你俩刚聊过什么**，所以能接着聊。回答上限 `chat.max_chars`（默认 90 字），
  比吐槽长一点，但仍然是大白话。
- 面板里保留最近几轮对话；对话**只存在这次运行里**，不写进 `memory.json`
  （记忆里仍然只记"它陪你看了什么"，不会被你俩的闲聊带歪画像）。
- 你这句会**当场**按类型过一遍（记录 / 分析 / 学习，见 ③，只在内存和控制台里）：
  问句就先把答案给清楚、带情绪就先跟着你的情绪走；这份统计不留文件，下次启动是干净的。
- **它先弄清「你这句话是冲谁说的」**：跟你打招呼、问它自己在干嘛（「你好」「你在干嘛呢」），
  和问视频里的事，是两回事——前者要它用自己的口吻接你，后者才去翻看片笔记。
  本地认出来就在这一轮提示词里说死（`persona.user_focus_note`），免得它像以前那样
  拿视频剧情答「你好」、或者把你的问句换个字抛回来（问「你在干嘛呢」→答「他在干嘛呢？」）。
  真抛回来了，还有一道本地闸当场再要一句（`humanstyle.looks_like_question_echo`）。
- **「主动搭话」和「回你话」是两条路**：前者是它自己憋不住开的口（见 ⑤），后者是你先说话它才答
  （这一节）；两条提示词各自写清自己是哪一种，不会互相串。
- 语音走 **Windows 自带的语音识别**（`System.Speech`，`pet/asr.ps1` 那层壳），
  和 OCR 一样是离线、零安装、不上传音频的；识别完默认**先填进输入框**让你确认
  （识别错一个字不用重说），想直接发就把 `chat.voice_auto_send` 改成 `true`。
- 想用英文识别就把 `asr.culture` 改成 `en-US`（系统里得有对应语音包）；
  识别时长 `asr.seconds` 默认 6 秒，说完安静下来它会自己提前结束。

默认每小时最多主动开口 3 次、两次之间至少隔 10 分钟（`proactive` 那一节能调）；它默认就开着，
不用去菜单里打开。

**⑦ 看片笔记：视频一刷出来，它先"读完"再聊**

以前它只会看「当前这一眼」，你问它「刚才那男的说啥来着」，它基本答不上来。
现在多了一层**看片笔记**（`pet/watchlog.py`）：

- **换视频的那一刻就先读一遍**：画面指纹跳变超过 `capture.scene_cut_threshold`（默认 0.14，
  普通播放不会触发）时，它不等冷却、也不吭声，先安安静静把这一眼读成一份笔记——
  主题 / 内容 / 看点 / 人物 / 地点 / 关键词；**是游戏的话还会多记三样**：
  **玩法 / 画风 / 玩家群体**（"搜刮跑毒 / 写实军武 / 硬核老玩家"这种）——
  类型只说"看哪一类"，这三样才说"具体好哪一口"，它们会跟着类型一起进口味档案
  （`taste.style_profile`），接话的方向才应景。**搭同一次调用，不额外花钱**。
- **看的时候一直记**：之后每一眼的 5W1H、弹幕字幕、它自己说过的吐槽，都按时间排进一条时间线。
- **你一问它就翻笔记**：你说「他为什么不打怪」，它会拿问题里的字去时间线和笔记里做**本地检索**
  （字符二元组重合度，不花钱、不联网），把最相关的几条连同笔记一起塞进提示词，
  所以回答里能有具体细节，而不是「挺有意思的」。
- 笔记和时间线**都在内存里**，不写进 `memory.json`，也不会额外上传什么；换一支视频就把时间线清空，
  前面几支的笔记留最近 5 支备查。
- 花费：每换一支视频多一次请求（`capture.absorb_min_gap_sec` 默认 15 秒内不重复读，
  `capture.absorb_max_per_min` 默认每分钟最多读 6 次）。刷得飞快的时候它会自己收敛。
- 不想让它读就 `watch.enabled = false`，或者 `capture.absorb_enabled = false`（只留时间线，不额外请求）。
- **跟着你的进度看**（`capture.absorb_progress_step`，默认 `0.1`）：同一支片子你在 10% 和 在 60%
  看到的是**两段内容**，只拿开头那份笔记应付，说起来永远是开头那点事。所以进度每往前走 10%
  就重读一遍（`absorb_progress_min_gap_sec` 默认 20 秒内不重复读，防你拖进度条时连读）——
  **正在看的部分是一段段读完的**，笔记跟着进度长。
- **它会知道你现在看到哪了**：每一段读完留一条短记录（最多 8 条），连同「他这支已经看到 62%」
  一起进提示词，所以它能说"你前面不是还说他俩不熟吗"，也不会把还没演到的当剧透说出来
  （`worker._viewing_block()`）。
- 鼠标停在托盘图标上，提示里有一行「看片笔记：…」，能直接看到它现在读到哪一支。

**⑦·补 整集资料卡：认出"这是哪一集"，就先弄清楚它讲的是什么**（`pet/episode.py`，**默认关**）

看片笔记看完的是**眼前这一眼**。可你要是看的是《奔跑吧》第九季第 28 集，
它光看见"两个人在户外做任务"是不够的——你聊到这一集时它接不上话。

所以 `keyinfo` 从画面上的字里认出「节目名 + 季 + 集」之后，它会先**做一次功课**：
拿这个标题问一次模型"这一集讲了什么"（**纯文本**，不发图），存成一张资料卡
（梗概 / 人物 / 看点），之后吐槽、聊天、夸人全都拿它当背景——
就像它已经了解过整集内容一样。

- **认不出是哪一集就什么都不问**（只有节目名、没有季和集 = 不认）；
- **同一集只问一次**，答案存在本机 `episodes.json`，`episode.refresh_days` 之后才会重做；
- **模型说不知道就什么都不存**（提示词里写死"不知道就说不知道、不许编"），
  存下来之后也会告诉它"这是你的印象，说起来留点余地"，别当成铁板钉钉的事实；
- 想接自己的数据源：`episode.source` 填一条命令或 URL 模板（`{show}`/`{season}`/`{episode}`），
  它返回的文字会直接当资料卡。

> 说清楚边界：**它不会去下载、也不会去播放整集视频**——那需要视频源、登录态、
> 几十上百 MB 流量，还有版权问题，不是这个挂件该干的事。
> 这里做的是"把这一集是什么内容弄到手"，对"能不能接住你的话"来说效果是一样的。

> **`episode.enabled` 默认是 `false`**：既然扒不到原片，主线就改成了上面那条
> **「把正在看的部分一段段看完 + 跟着你的进度互动」**（本地进度条 + 定期重读，不额外花什么钱）。
> 想让它提前知道整集背景，再手动把 `episode.enabled` 打开。

**⑧ 上班的时候，它会提醒你照顾自己**

它擅长的是陪你看视频，不是照顾坐太久的人——你连着写三小时代码、屏幕一点变化都没有，
它就真的一句话不说。所以另起一套**只看钟点**的提醒（`pet/care.py`），跟吐槽完全无关：

| 提醒 | 默认间隔 | 文案 |
| --- | --- | --- |
| 喝口水 | 45 分钟 | 「嘴都干了吧，去接杯水」 |
| 站起来走两步 | 1 小时 | 「腰不要了？起来抻一下」 |
| 闭眼歇一会儿 | 1.5 小时 | 「眼睛该歇会儿了，闭十秒」 |

三道闸门，缺一道就变成话痨：**只在工作时间**（`work_start_hour` ~ `work_end_hour`，
默认 9→18，两头相等就是全天）、每件事各有各的间隔、两条提醒之间还至少隔
`min_gap_sec`（默认 10 分钟）。另外人不在（键鼠空闲超过 `active_idle_sec`，默认 5 分钟）
就先不提醒——提醒给谁看呢。文案全是本地写死的，**一条都不花接口钱**，没配 Key 也照说；
不想要就 `care.enabled = false`。

**⑨ 情绪价值：主动夸、主动关心**（都**不用你按键**）

- **主动夸 / 主动关心**（`proactive.content_nudge`，默认开）：这是"情绪价值"的**主要**那条路，
  不用你按任何键。它自己看你**正在干嘛**（`pet/keyinfo.py` 的 `activity_of`，纯本地判：
  认出来的游戏名 → 在打游戏；窗口标题像代码/文档 → 在干活；有看片笔记 → 在看视频），
  同一件事待够 `praise_after_min`（默认 20 分钟）就主动夸一句**具体的**——
  看剧夸你挑片的眼光、打游戏夸你刚才那一下操作、干活夸你这个人；
  待够 `care_after_min`（默认 50 分钟）就换成**关心**：先说身体（坐太久、眼睛），
  再针对你正在做的事给一句能落地的小建议（看剧的歇一集、打游戏的打完这局就起来、
  忙活的存个盘伸个懒腰）。认不出来（比如在桌面上发呆）就什么都不说——
  夸空话比不夸更尴尬；同一件事 `content_cooldown_min`（默认 30 分钟）内不重复。
  这一条会额外调一次模型，没配 Key / 关掉 `model_nudge` 时用本地台词顶上。
- **你诉苦的时候，它只做两件事**：你在打字框或语音里说了难受的话
  （`humanstyle.needs_comfort`：认得出"好累""烦""难受""委屈""唉"这一类的），
  这一轮它就不接梗、不讲道理、不给方案清单，只**先接住情绪 + 抱抱你**。
  模型偶尔只顾着讲道理，本地会补一句「抱抱」；连模型都用不了时，
  直接说本地那句「抱抱收到啦 ❤」，这一句不花接口钱。
- **"出门"只有一个门：去谁家串门**（见上面「⑧ 好友系统」）。以前菜单和面板里还摆着一个
  「去别的屏幕逛逛（本机）」——那是在**你自己屏幕上**换块屏待一会儿
  （`ui.visit_seconds`，默认 25 秒），跟跨电脑的串门是两回事，摆在一起只会让人以为出门有两个门，
  所以**整项删掉了**（`FriendPanel.strollRequested` 信号一并删）。
  `PetWindow.visit()` 和 `ui.visit_seconds` 都还在（谁想调都行，冒烟测试也用它），
  只是界面上不再有那个按钮。

> 以前那两条「夸夸我（`Ctrl + Alt + C`）」「抱抱我（`Ctrl + Alt + H`）」热键和菜单项
> **已经撤掉**了：现在"夸"和"抱"都是它自己看情况给（上面那两条），不用你开口要。
> `hotkey.compliment` / `hotkey.hug` 这两个配置项也一并删了；后来剩下的那几个热键
> 也整套撤了，入口全回到右键菜单（见上面「④ 全部用鼠标」）。

**⑩ 这支视频你到底看完没有（底部进度条）**

`taste.json` 的兴趣分里"看完"值 +2 分，但以前这个 `ended` 永远是 `False`——程序从来不知道
视频播到哪了，问模型它也看不出进度。现在多了一条**纯本地的进度条识别**（`pet/progress.py`）：

- 只在画面**底部那一截**找：一行里有**两段又长又平**的颜色（已播 + 未播）、中间隔着一道边、
  整条横跨播放器大半宽度；还要满足一条硬条件——**它得浮在画面上**（把这一段往上挪几像素，
  颜色就不一样了），这条能把黑边、纯色底、播放器外壳全都排除掉。
- 认出来就记下**这支视频见过的最大进度**（不是最后一眼的进度：视频播到头时进度条会被重播画面
  盖掉，最后一眼往往量不到），结算时 ≥ `taste.end_ratio`（默认 85%）就算看完，那 +2 分才真正算进去。
- **认不出来就什么都不做**：`ended` 还是 `False`，跟以前的版本一模一样——宁可少算 2 分，
  也不能把"只看了三分之一"误判成看完。半透明的进度条（盖在花花的视频上）也会被放过。
- 全是本地像素计算，不联网、不花钱；不想要就 `taste.progress_bar = false`。
- 量到的进度会打一行日志（`[taste] 进度条快到尽头了（第 331 行 · 93%（20~619））`），
  想知道它到底认没认出来，盯着控制台就行。

**⑧ 好友系统：两台电脑的桌宠互相串门**

两台都开着挂件的电脑，只要**彼此看得见**（同一个局域网里，或者用 ZeroTier / Tailscale
组个虚拟局域网），就能让一只去对方屏幕上坐一会儿：自己打招呼、跟对方那只唠两句，
你也能戳它、跟它说话，到点（或者你喊一声）自己回家。

| 想干什么 | 在哪儿做 |
| --- | --- |
| 配对 | 右键挂件 →「好友系统（串门 / 加好友）…」→ 点「复制名片」，把那一行发给朋友；他粘进自己面板的输入框 →「加好友」 |
| 去串门 | 好友那一行点「去串门」——对方屏幕上会多一句「XX 在门口」，等他点「让它进来」 |
| 放它进来 | 门口那一栏点「让它进来」/「今天先不」；也可以把 `friends.auto_accept` 设成 `true`，好友的宠物直接放进来 |
| 跟客人说话 | 客人那一行点「跟它说句话…」（打字）或「戳一下」——话送到它那台机器上，由它生成回答再送回来 |
| 打听在忙啥 | 在做客 / 家里有客人时点「问它在忙啥」——对方**在它自己那台机器上**拼一句「我主人这会儿在看视频 / 在打游戏 / 在干活」回来（见下面「在干嘛」那段） |
| 两只一起玩 | 客人那一行 / 在做客那一栏点「一起玩一下」——两边**同时**做一个动作（击掌、撞拳、抱一下、躲猫猫…）；说哪句话还是各在自己那台机器上生成。客人待在屏幕上的时候，它俩会**自己每 30 秒玩一次**（`friends.play_gap_sec`） |
| 请它回家 | 客人那一行点「请它回家」；自家那只在别人家时，面板顶上会多一行「喊它回家」/「戳对方那只」 |

- **对方设备不在工作中**：敲门、或者等在门口的时候连不上（对方关了程序 / 关机 / 不在同一张网），
  面板里会直说「**对方设备不在工作中**——连不上 XX 那台机器」，不拿"对方不方便"糊过去——
  那听着像是人家不想理你，其实是机器根本不在线。
- **出门的门只有一个**：加了好友之后，好友那一行点「去串门」——这就是出门。以前右键菜单里
  那一项「去别的屏幕逛逛」（在你自己屏幕上换块屏待一会儿）已经整项删掉了。

- **两台机器各养各的脑子**：我的宠物说哪句话，永远在我这台机器上调模型；对方的宠物说哪句话，
  永远在它那台机器上生成。过网的只有「我是谁 + 我长什么样 + 我要说的这一句 +
  我主人这会儿大概在忙什么」——**截图、OCR、长期记忆、看片记录一个字都不发出去**。
- **好友在干嘛**（`pet/doing.py`）：出访时我的宠物顺口带一句「我主人这会儿在忙什么」，
  到了人家那边，主人家的招呼就能接上；在做客 / 家里有客人时也能反过来问一句
  （`net.PATH_DOING`）。三件事说清楚：
  - 答的那句话是**对方在它自己那台机器上拼的**，不调模型、零成本、零延迟；
  - 尺度由 `friends.share_doing` 把关：`0` 一个字都不说，`1` 只说大类
    （在打游戏 / 在看视频 / 在干活 / 在忙别的），`2`（默认）连游戏名、片名也说——
    但**「干活」那件永远不带名字**，因为它手里那点就是窗口标题原文；
  - 原始窗口标题、截图永远不出那台机器；`friends.ask_doing` 关掉就不打听。
- **两只一起玩**（`pet/play.py`）：动作表里有击掌 / 撞拳 / 抱一下 / 一起晃 / 躲猫猫 /
  拍一拍 / 抛媚眼。动作名（`highfive` 这种）过网，两边各自播**同一个**动作，
  所以看起来是同步的；说哪句话还是各在自己那台机器上生成。
  - **每套动作都有自己的帧**：`assets/pet/<动作名>_00.png … _11.png`（跟 `idle_*` / `talk_*`
    一个命名规则），内置形象那套是 `tools/make_pet.py` 生成的——抖法写在 `pet/play.py` 的动作表里，
    想换成手画的直接覆盖同名文件即可。有帧就按动作进度播；哪套没放帧也不冷场，
    它会**蹦一下 + 说配词**（不会崩，只是不做那个动作）。
  - 客人还在屏幕上时，它俩**自己每 `friends.play_gap_sec` 秒**（默认 30 秒）玩一次；
    `friends.play_rounds` 默认 `0` = 不封顶（客人不走就一直玩），想只玩几次就填个数
    （`play_gap_sec` 填 0 就是不自动玩，只在你说「一起玩一下」时玩）。
- **靠什么认出对方**：`pet_id`（首次启动随机生成，写进 `friends.json`），不是 IP、也不是名字——
  对方改了宠物名、换了路由器，你这边还是同一个人，只是地址会被更新。所以**只能靠交换名片配对**，
  谁也没法凭空连上你。
- 每次请求都要**对暗号**：口令（`friends.token`，首次启动自动生成）不对直接 403。
  **名片别往群里发**——拿到名片的人，等于能让他的宠物来你屏幕上坐坐。
- 默认端口 `8799`（`friends.port`），监听在 `friends.listen`（默认 `0.0.0.0` = 所有网卡）；
  Windows 防火墙第一次会问你放不放行，**只勾"专用网络"**就够了。端口被占时面板会直说
  "门没开"，换一个 `friends.port` 即可（两边不用一样）。
- 客人长什么样：优先用对方寄来的几张待机帧（`friends.share_frames`，几百 KB），
  没图就退化成内置矢量形象；表情照 mood 标签走，说话走它自己的小气泡窗口（可以拖着挪地方）。
- 同时最多 `friends.max_guests`（默认 2）只客人在屏幕上；`friends.visit_seconds`（默认 15 分钟）
  是一趟待多久；两只宠物见面会自动来回 `friends.pet_chat_rounds`（默认 3）句，之后就得靠你搭话。
- 边界都在明面上：谁来过、说了什么只写本地 `data/visits.json`（`friends.log`），
  **不进长期记忆**；好友簿在 `friends.json`，收下来的形象帧在 `data/guests/`——不想留就删。
- 不想要就 `friends.enabled = false`，或者干脆别给人名片。

> 这一层是**纯局域网直连**（标准库 `http.server` 起个小服务 + 项目里已有的 `requests` 当客户端），
> 不经过任何中转服务器——跟"截图不出本机"是同一个取向。想跨公网就自己想办法让两边看得见
> 对方端口（端口映射，或 ZeroTier / Tailscale 这类虚拟局域网）：对代码来说，对方永远只是
> "一个地址 + 一个端口"（`pet/net.py`）。
>
> 回归测试是**真开两个端口、真发 HTTP** 跑一整趟串门（`tools/smoke_test.py` 的
> 「好友系统：串门整条路」）——里面那几条最容易出事的地方都钉住了：一个进程里开着两个门房时
> 口令必须各认各的；对方一点头就招呼的那句话比敲门人下一次来问更早到，必须接得住。

## 安装

### 方式一：直接下载打包好的（不用装 Python）

Releases 页面下载 `ScreenPet-<版本>.zip` → 解压到任意文件夹 → 双击 `ScreenPet.exe`。
第一次用：右键它 →「打开配置文件」，把 `provider` 改掉、填上 `api_key`，重启一下。

### 方式二：从源码跑（要改代码就走这条）

需要 Windows + Python 3.10+（已在 3.13 上验证）。

```bat
cd screen-pet
python -m pip install -r requirements.txt
```

源码模式下 `config.json` / `memory.json` / `data/` 就在项目根目录——这是老用户的既有位置，
一直没变过（打包版才换到 `%APPDATA%`，见 `pet/paths.py`）。

## 快速开始

**第一步：先看形象（不需要任何 Key）**

```bat
python main.py
```

默认 `provider = "mock"`，不联网也能跑：它会根据画面亮度和色调胡乱吐槽，
刚好用来调形象大小、位置和气泡样式。

**嫌黑框碍眼就双击 `run.cmd`**：它用 `pythonw` 起挂件，屏幕边上只有挂件、没有控制台，
日志照样追加写进 `run.out`（想在终端里看实时日志，就直接 `python main.py`）。

**第二步：接一个真模型**

最省事的办法是双击项目根目录的 `set-key.cmd`：选一家接口 → 粘 Key（输入不回显）
→ 它立刻试连一次告诉你通不通，还能顺手把挂件重启到新配置。

```bat
set-key.cmd              :: 双击也行：选 provider → 粘 Key → 试连
set-key.cmd --check      :: 只测当前配置通不通，不改文件
set-key.cmd --restart    :: 填完直接重启挂件（先结束在跑的那个）
set-key.cmd --mock       :: 回离线模式（清掉 Key）
```

也可以手工来：

1. 先点一下挂件（右键）→「打开配置文件」，或直接编辑 `config.json`；
2. 把 `provider` 换成下面任意一个，并填 `api_key`：

   | provider | 说明 | 默认模型 |
   | --- | --- | --- |
   | `zhipu` | 智谱，`glm-4v-flash` 免费额度大，**推荐先用这个** | glm-4v-flash |
   | `dashscope` | 阿里通义千问 | qwen-vl-max-latest |
   | `siliconflow` | 硅基流动 | Qwen/Qwen2.5-VL-32B-Instruct |
   | `openai` | OpenAI | gpt-4o-mini |
   | `ollama` | 本地跑，免费但要显卡 | qwen2.5vl:7b |

   `base_url` / `model` 留空就会用上表的默认值；
3. 立刻验证一下（不弹窗，只打印结果）：

   ```bat
   python main.py --selftest
   ```

   Key 也可以不写进文件，改用环境变量：`set PET_API_KEY=xxxxx`。

   > **改配置前先退出挂件**：挂件退出时会把内存里的那份配置写回 `config.json`，
   > 开着它改文件会被覆盖掉（包括刚填好的 Key）。用 `set-key.cmd --restart` 就不必操这个心。

**第三步：框选"只看视频那一块"**

右键挂件 →「手动划观看范围…」，屏幕会铺一层半透明的框选界面，**一个入口管两种情况**：

| 在这个界面里 | 结果 |
| --- | --- |
| 拖一个矩形（一般就是播放器画面） | 只看这一块，既省钱又不会被你的微信打扰 |
| 什么都不拖、直接双击（或按 `F`） | 整块屏都看（取消原来的框选） |
| 右键 / `Esc` | 不改，保持原来的样子 |

存下来之后会写进 `config.json` 的 `capture.region`。也可以纯命令行做：`python main.py --pick-region`。

> 以前这里是菜单里两项——「只看一小块地方…」和「整块屏都看」，现在合成同一个界面：
> 进去想划就划，不想划就双击，少一层"我该点哪个"。

## 交互

### 气泡和菜单长什么样

一块**深色玻璃**：上面浅一点的蓝黑渐变到底部更深的蓝黑，四周一圈**情绪色的柔光边**（外圈宽而淡、
内圈细而实），顶上一条横向高光，圆角 18、尾巴是两条贝塞尔收出来的圆头（不是硬三角）。
字是 13 号、字距松 0.4，底下先描一层 1px 的淡影——视频再花也读得清。
冒出来的时候会**从下往上轻轻弹一下**（200 毫秒，只偏绘制、不动窗口位置，免得跟定位逻辑打架）。

右键菜单跟它一套语言：同样的深色玻璃、12 圆角、青色分组标题，悬停是一层青色柔光，
勾选项走了系统的对勾（样式表里不写 `QMenu::indicator`；「主动搭话」那个开关撤掉之后，
菜单里已经没有勾选项了，这条口径留着）。分组标题用的是真正的 `QLabel`
（`QMenu` 一挂样式表，`addSection()` 的字就画不出来了，Qt 的老毛病）。

> 样子都在 `pet/window.py` 顶上的常量里（`RADIUS` / `PAD_X` / `MENU_QSS`）和 `BubbleWindow.paintEvent()`，
> 想换配色改 `pet/sprite.py` 的 `ACCENT` 与 `pet/mood.py` 里各情绪的 `color` 就行。
> 情绪**依然不上界面**：一个标签、一个小胶囊都不画，只有边框颜色在动。

### 进气泡之前还要过几道手

模型给两行（台词 + 场景），**只有第一行进气泡**；进了气泡的那句话还要再过一遍
（`persona.clean_reply`）：

| 规则 | 怎么做 | 为什么 |
| --- | --- | --- |
| **一律简体** | 繁→简的字级对照表（`pet/zh.py`，840 个字，同形的字不写，查不到的原样留着） | 它偶尔整句繁体（现场气泡：「因為求折磨這個犧牲太大了我覺得」，多半是照着画面上的繁体字幕说的）。提示词里写"用简体"拦不住小模型，所以在程序这一侧兜住——**不引 opencc / zhconv**：这是个零安装的小挂件，不想为了几个字多装一个包 |
| **页面上抓来的标题不是话** | `humanstyle.looks_like_title()`：书名号里的作品名 / 话题标签（`#复联`）/ 标题噪声词（万字深拆 · 幕后解读 · 剧情设定 · 完整版 · 第X期 · 中字 4K…）/ 尾巴上的括号补充——**有标题特征、又看不出在跟人说话**（没有问号感叹号，没有「我你咱真太别不了」这种口气词）才丢 | 现场气泡里出现过整条 **「《复仇者联盟3》剧情设定细节探案幕后解读」**——那是页面上那支视频的标题，它照着念了一遍。这句一个「内部字眼」都不带，块头那道闸（`looks_like_internal`）认不出；「念屏幕」那道闸又要先剥掉块头才生效，所以整条漏了过去。现在这种句子不进气泡，并且当场再要一句（`last_drop = "title"`）；带了自己的反应（「这解说讲得真啰嗦」）照说不误 |
| **它那套机器不是话** | `humanstyle.looks_like_meta_talk()`：① **机器词**（语料 / 知识点 / 资料卡 / 记忆里 / 数据库 / 词条 / 归档 / 做功课 / 补课…）；② **进行体**的自我汇报（「我在学 / 我在记 / 我在补课 / 我刚学到了」）；③ **看片笔记 / 资料卡的字段形状**（一行里两个以上 `类型：` `看点：` 这种字段，或者整句以字段名开头；「别人问：… 我接：…」这种自问自答也算）→ 整句丢掉，当场再要一句 | 用户要的是个**陪看的朋友，不是一台会报进度的机器**：现场气泡里出现过「我刚学到一个知识点：长按就能保存」，日志里还见过 `键名：类型 / 答案：影视综艺 / 键名：主题` 这种把看片笔记字段念一遍的。**完成体的「我记住了 / 我记下了」故意放行**——那是熟人聊天里正常的"我知道了"，写进语料也是好样本；只有跟机器词一起出现（「记进记忆里了」）才丢 |
| **只剩标签就不是话** | `scene.is_label_only()`：整句只剩「场景 / 未知 / 5W1H」这类字样（括号、冒号先摘掉）→ 整句丢掉，这一轮不说 | 现场气泡里出现过 **「场景：」** 和 **「未知」**。图二那条的来路是模型把**情绪标签和空的场景行写在了一行**（`[无语] 场景：`）：摘标签之前场景判断在行首失配，整行被当成台词念了出去，标点一清就只剩俩字 |
| 标点只留 ，。？！… 和引号、书名号、动作括号 | `tidy_marks()`：「/」处只念第一句（那是它没拿定主意的备选）、`...`／`。。。`→`…`、重复标点合并、末尾句号去掉 | 屏幕上出现「A / B / C」那种草稿串，看着就不像在说话 |
| 太长就在句读处断开 | `fit()`：不从句子中间劈 | 气泡里读着别拗 |

> 这几道闸都有回归测试盯着（`tools/smoke_test.py` 的
> 「内部信息不许进气泡（块头剥掉 / 念屏幕就丢）」「抓来的标题不许进气泡 / 语料」
> 「它那套机器不许进气泡（我在学 / 念语料 / 念资料卡）」和
> 「一律简体（繁→简零依赖）+「场景：」这种只剩标签的不进气泡」），
> 连那几张现场气泡截图都写进断言里了——改坏了会当场红。
> 改完 `.py` 记得**重启挂件**再看效果（跑着的进程还是老代码）。

| 操作 | 效果 |
| --- | --- |
| **左键点一下** | **随机演一个动作**（池子见 `pet/states.py` 的 `CLICK_ACTIONS`），不再弹输入框 |
| 左键拖动 | 把它挪到任意位置（比如屏幕左边）——拖过就不算"点了一下"，不会演动作 |
| 双击 | 被戳一下 + 暂停 / 继续看 |
| 右键 | 打开菜单，按「**陪你看 / 跟我说说话 / 我自己的事**」三组排好（以前五组，「看哪儿」并进了「陪你看」、「逗它一下」并进了"点一下"） |
| 托盘图标单击 | 显示 / 隐藏挂件（和菜单里那项「显示挂件」是同一个开关） |
| 托盘右键 | **只有一项「显示挂件」**（勾上 = 挂件在屏幕上）。全部命令都在挂件右键菜单里，托盘只管"放出来 / 收回去"；鼠标停在托盘图标上会浮出状态：我懂你什么、现在在看什么、补课补到哪儿了（锁着某个程序时再多一行「监视范围」） |
| 鼠标停在它身上 | 0.9 秒后冲你**挥手**（同一只 25 秒内只挥一次，见 `pet/states.py` 的 `REACTIONS`） |
| 把它拖起来又放下 | 落地**蹦一下** |

右键 →「我自己的事」→「把我钉在这儿（鼠标点不到我）」会把它整个变成鼠标透明——适合摆好位置后锁住，
避免挡住视频里的按钮。**锁着的时候不用解锁也能用**：先鼠标移上去（挂件是圆的，圆内算碰到），
停 `ui.lock_hover_delay_ms`（默认 200 毫秒）它会**临时把穿透关掉**（右下角的小锁会变色、
光标变成手型），这时右键、拖动、双击照常用；鼠标一离开就自动恢复穿透。
锁上之后照样点得回来：鼠标压上去临时解锁，菜单里那一项这时写的是「松开（鼠标能点到我了）」。
右下角有小锁图标代表当前是锁定状态。
不想让它"碰到就亮"（比如你就想让它彻底透明）把 `ui.lock_hover_unlock` 改成 `false`。

## 换成你自己的形象

内置形象是程序用代码画的（一只叫「黄豆」的史莱姆），只是为了先跑起来。

### 最省事：右键菜单「设计我的形象…」（调完当场换装）

不想画图、也懒得碰配置的走这条：**右键挂件 → 「设计我的形象…」**。
弹出来的窗口左边拧旋钮、右边就是它——用的就是屏幕上那个渲染器，看到什么就是什么。

- 能拧：**六块颜色**（身色上 / 身色下 / 描边 / 眼珠 / 腮红 / 强调色）、
  **身形**（史莱姆 / 圆团子 / 方块 / 水滴）、**眼睛**、**嘴**、**身宽**、**身高**，
  外加「腮红 / 头顶的触角 / 身上那点高光 / 脚下的影子」几个开关；懒得挑就按「随机一套」。
  预览旁边还站着一排情绪样张（开心 / 无语 / 激动 / 好奇）。
- **改一下当场换装**：从菜单开出来的这一份直接给桌宠换上，不用重启。
  想一边调一边看整只挂件，就把下面那个「装了图片帧也先用这套」勾上（配置里是
  `ui.prefer_vector`）——不然 `assets/pet` 里有帧时屏幕上还是播帧。
- **挑了眼睛 / 嘴只管待机**：情绪照旧走老那套表情（开心弯月眼、无语一条线…）。
  想让喜怒哀乐都照你挑的画，勾上「情绪也用这套表情」（配置里是 `pet_style.face_locked`）。
- **满意了就点「保存到配置」**：写进 `config.json` 的 `ui.pet_style`，
  而且**只写和预设不一样的那几项**，所以预设以后微调你也跟得上：

  ```json
  "ui": {
    "pet_style": {"preset": "peach", "body_shape": "round"}
  }
  ```

  图省事整节写一个预设名也行：`"pet_style": "mint"`。
  八套预设：黄豆（默认）/ 蜜桃 / 薄荷 / 葡萄 / 焦糖 / 雪团 / 夜色 / 水墨。
- **想把这一套变成图片帧**（拿去打包 / 给别人）：点「导出源图」，会存一张 768×768 的白底
  `assets/source/pet_design.png`，然后

  ```bat
  python tools\make_pet.py assets\source\pet_design.png
  ```

  抠背景那一步认白底，所以导出时**故意关掉地面阴影**——那团半透明灰会被当成背景一起抠掉。
- 颜色写错了 / 数值超范围都不要紧：那一项退回该预设的值，并留一句话（启动时打 `[style] …`，
  设计器窗口里也显示），挂件照常跑。**默认值就是原来那套**，没配过 `ui.pet_style` 长相一点没变。
- 命令行也一样能开：`python tools\design_pet.py`（从 `config.json` 现在的长相开始）、
  `python tools\design_pet.py mint`（从某个预设开始）、
  `python tools\design_pet.py --no-config`（纯试玩，不读也不写配置）。
  这样开出来的只能改文件，**重启挂件才生效**；想在挂件上当场换装就走右键菜单那条路。

下面那条是"自己画"的路线：你自己的形象丢进 `assets/pet/` 就行，命名规则见 `assets/pet/README.txt`：

```
assets/pet/idle_0.png ...              待机帧
assets/pet/talk_0.png ...               说话帧（没有就用待机帧）
assets/pet/excited_0.png ...            可选：给某个情绪单独画帧
assets/pet/highfive_00.png ...          可选：串门动作的帧（highfive / bump / hug / sway /
                                        peekaboo / pat / wink，跟情绪帧一套规则）
```

透明底 PNG、正方形，建议 256px 以上；帧按文件名排序播放（默认 8fps）。
没给某个情绪准备帧也不要紧，会自动退回待机/说话帧并叠上对应的弹跳和歪头。

### 偷懒版：把自拍贴到它脸上

不想画图，只想让黄豆长自己的脸：

```bat
python tools\paste_face.py assets\source\my_face.jpg --install
```

把自拍存成 `assets\source\my_face.jpg`（或者把路径直接写在命令里），它会把照片里
那块正方形裁成圆形、缩到脑袋里贴上去，外面留一圈黄边，然后自动生成整套动效帧
写进 `assets/pet/`，重启挂件就换了张脸。身体和那双鞋还是黄豆的。

脸没裁准（额头被切、脸偏了）就调这几个：

```bat
python tools\paste_face.py assets\source\my_face.jpg --face-box 80,40,240,300   # 手动框出照片里脸的位置
python tools\paste_face.py assets\source\my_face.jpg --crop-ratio 0.75 --center 0.5,0.55
python tools\paste_face.py assets\source\my_face.jpg --zoom 0.92 --shift 0,-0.05 --preview 对比.png
```

`--preview` 会存一张「左：原脑袋　右：贴好的脸」的放大对比图，贴完先看一眼再 `--install`。
想换回原版黄豆：`python tools\make_pet.py assets\source\pet_src.png`；
想换回内置矢量形象：`python tools\make_pet.py --clear`。

**换完想马上看到效果**：双击 `regen.cmd`（= 重新生成一遍 → 自动收掉旧挂件 → 再起一个新的），
一条命令搞定，不用自己先关再开。带参数的写法：`regen.cmd --heal 6 --shade 0.7`。

**不用自己留白**：挂件窗口是圆的（按窗口边长裁椭圆，圆外点不到），装帧时程序会统一
「裁掉透明边 → 按外接矩形的角刚好落在圆上缩放 → 居中」，所以把人物画满整张画布也不会
被圆切成直边（以前就是这里翻车：脚和身体两侧被切掉）。想让形象更大或更小，
调 `ui.pet_size` 就行——窗口和形象一起变，圆的安全区永远算得对。
（**动作帧 / 日常状态帧不参与这个框**：蹦一下、伸个懒腰本来就该往外冒一点，让它们一起算
会把框撑大，于是"站着不动"的时候人也跟着变小。它们跟基础帧共用同一份缩放和居中，
只裁到画布边上为止——冒到圆内的留着，冒到圆外的照旧被切掉。）
渲染效果可以随时用 `python tools/render_preview.py preview.png` 看一眼
（预览图上**一个字都不写**：情绪不写标签、气泡不写"示例"图注、表情也不写对照表——
你在预览里看到的就是屏幕上看到的那个样子）。

### 把这一整套帧打包带走（素材包）

自己画的、或者用源图生成好的这一整套帧，可以一条命令打成「素材包」拿走 / 给别人的宠物用：

```bat
pack-assets.cmd                                :: 双击（内部就是下面那条）
python tools\pack_assets.py                    :: 下载 → 抠透明 → 归类 → 压缩
python tools\pack_assets.py --url <图片直链>    :: 先下载源图，再照上面走一遍
python tools\pack_assets.py --no-cutout        :: 跳过重生成：只归类 + 打包现有的帧
python tools\pack_assets.py --list             :: 只归类核对，不出包
```

四步各干什么：

| 步骤 | 干什么 |
| --- | --- |
| 下载 | 给了 `--url` 就把源图抓进 `assets/source/`；没给就跳过，用本地那张（默认和 `regen.cmd` 里那行 `SRC` 是同一张） |
| 抠透明 | 源图交给 `tools/make_pet.py`（抠背景 → 裁边 → 缩放），生成整套 `<状态名>_NN.png` |
| 归类 | 按 `pet/states.py` / `pet/play.py` / `pet/mood.py` 三张真源表分组核对，每套写清「几张帧 + 建议时长」；缺哪套只提示，不报错 |
| 压缩 | 打成 `dist\桌宠素材包-v<版本>.zip`（帧 + `README.txt` + `清单.txt`） |

包里是**现成的英文命名**（`idle_00.png` / `walk_00.png` / `highfive_00.png`…），
名字就是 `pet/states.py` 的 `Pose.key`、`pet/play.py` 的 `Move.key`——
解压后把 `assets` 覆盖到项目根目录、重启挂件就生效，**一行代码都不用改**。
当前这套打完是 **33 套 / 396 帧**（基础帧 2 + 情绪帧 8 + 串门动作 7 + 日常状态 16，各 12 帧）。

顺手的两件事：`清单.txt` 里列着每套的帧数和建议时长（循环的 = 转一圈，一次性的 = 播一遍）；
重新生成了帧的话，脚本最后会用 `tools/restart_pet.py` 把挂件重启一遍换上新形象。

> 想留住**手画**的帧（别被重新生成覆盖）：用 `--no-cutout` 只打包现有的；
> 不想让它顺手重启挂件就加 `--no-restart`。

### 眼睛跟着鼠标转

`python tools\make_pet.py 你的图.png` 会**自动**把两只**眼珠**抠出来，做成独立的一层，
再生成整套帧。之后挂件就会让眼珠朝着鼠标的方向转：

```bat
python tools\make_pet.py assets\source\pet_src.png          # 自动找眼睛 + 生成帧
python tools\make_pet.py assets\source\pet_src.png --no-eyes   # 不想让它跟鼠标
python tools\make_pet.py assets\source\pet_src.png --eye-travel 0.6   # 眼珠转得更夸张
```

抠下来的**只有眼珠本身**（虹膜 + 里面的高光）：底图里对应的位置用**眼珠外圈的颜色**糊上，
眼线、眼睑、眼白、周围的皮肤一概留在底图上不动——所以动起来是"眼珠在眼眶里转"。
（以前把"圆内所有深色"都算成眼珠，而这只小人在 256 画布上眼线 + 眼睑 + 虹膜连成一整块，
抠出来的其实是**整只眼**，鼠标一动就像有人把眼睛推来推去。）

它会在 `assets/pet/` 里多写两个文件（都是自动生成的，别手改）：

| 文件 | 作用 |
| --- | --- |
| `eye_layer.png` | 眼珠那一层（透明底，画布对齐；只有眼珠，不含眼白和眼睑） |
| `eye_layer.json` | 两只眼珠的位置/半径 + 每帧的身体变换矩阵 |

渲染时是「先画身体那一帧 → 再把眼珠层按同一个身体变换叠回去 → 最后按鼠标方向偏一点」。
所以身体上下浮动的时候眼珠不会从眼眶里飘出来。静止时看起来和原图一模一样。

找得准不准，跑完直接看 `assets/source/eye_preview.png` 那张三联图：
**左**=原图 + 红圈（找眼睛时认下的整只眼）+ 绿圈（**真正会跟着鼠标动的那一块**，得明显比红圈小）、
**中**=抠出来的眼珠层、**右**=抹掉眼珠后的底图。
红圈没套住眼珠就手动指一下（画布像素坐标，256×256 画布上）：

```bat
python tools\make_pet.py assets\source\pet_src.png --eyes 96,104,13,160,104,13
```

其它相关开关：

* `ui.eye_tracking`（默认 `true`）：总开关。
* `ui.eye_follow_px`（默认 `320`）：鼠标离挂件多远算"看到最边上"，调小眼珠更灵敏。
* 暂停（`Ctrl+Alt+P`）时眼珠不追鼠标。

注意：这套做法是**只动眼珠**，不动眼皮，所以不会眨眼（眨眼要另画帧）。

### 摸着下巴思考（食指轻轻敲）

同一个命令还会顺便找出**搭在下巴上的那只手**，把竖着的那根食指抠成 `hand_layer.png`，
之后挂件就会隔几秒**轻轻敲两下**下巴，做出"摸着下巴想事情"的样子：

```bat
python tools\make_pet.py assets\source\pet_src.png            # 自动找手 + 生成
python tools\make_pet.py assets\source\pet_src.png --no-hand    # 不要这个动作
python tools\make_pet.py assets\source\pet_src.png --tap-lift 9 --tap-period 3.5   # 敲得更明显、更慢
```

| 参数 | 作用 | 默认 |
| --- | --- | --- |
| `--tap-lift` | 敲一下把贴片**上沿**抬高多少（256×256 画布上的像素；指尖实际抬起约 0.8 倍） | 6（168px 的挂件上约 4 个屏幕像素） |
| `--tap-period` | 敲的周期（秒）：一个周期里轻敲两下，其余时间贴着下巴 | 2.4 秒 |
| `ui.hand_tap` | 运行时总开关（不用重新生成形象） | `true` |

动作是**以指根为锚点把这层往上拉伸一点点**（不是整块往上挪）：指根那一行原地不动、
越靠近指尖抬得越多，所以手和手指之间**永远连着**。早先是整块平移，贴片下沿压在指根上，
一挪就在两者之间裂开一条缝（补色的那块露出来），现场看着就是"手在自己伸缩"。

找得准不准，跑完看 `assets/source/hand_preview.png`：**左**=原图 + 红框、**中**=抠出来的食指层、
**右**=抹掉食指后的底图。框歪了就手动指（画布像素坐标，256×256 画布上）：

```bat
python tools\make_pet.py assets\source\pet_src.png --hand-box 150,127,199,164
```

注意三点：

* 只会**往上**抬，不会往下戳进下巴。
* 跟着一起动的是**红框里那一整块**，所以框别留太多白——留白大了，抬起来的就是一整片手套，
  看着又像手在伸缩。默认按指头高度的 25% 留白，不够贴合就手动 `--hand-box` 收一收。
* 手和眼睛都找不到时，会自动跳过对应的动作，形象照常能用。

## 隐私与成本

* 只上传**观看区域**的静态截图，不录音、不录屏、不保存历史图片。
* OCR 在**本机**完成（Windows 自带引擎或本地 rapidocr），文字不会单独上传，
  只是随该帧的提示词一起交给模型。
* 前台窗口标题也只在本地读，随提示词一起发送；不想要就把 `ocr.window_title` 关掉。
* 长期记忆全部存在本机 `memory.json`，可以随时打开看或一键清空，不会同步到任何地方。
* `dHash` 相似度过滤 + 冷却 + 每分钟上限，挂机一整天也很少真正调用模型。
* **主动搭话**："你走开了 / 你回来了 / 深夜劝睡"这三句完全在本地判断（Windows 的键鼠空闲时间 + 本机时钟），
  不联网也不花钱；"画面静止 / 久未开口 / 记忆话头"这三种会额外调一次模型，但最多每小时 3 次。
  把 `proactive.model_nudge` 关掉就一次都不会多调；关掉 `time_aware` / `topic_from_memory`
  就分别只剩免费台词、以及不带记忆的通用搭话。翻记忆找话头只是**读** `memory.json`，
  不会往里写东西。
* **另外两条也都在本地、也都不花钱**：上班健康提醒（`care`）、底部进度条识别
  （`taste.progress_bar`）。进度条只是在本机数几行像素，不读字、不联网、也不额外调用模型。
* **边看边学**（`learn`）也全是本地的、不额外花一分钱：它只是把**已经在读**的那份 OCR 结果
  再过一遍本地判据（窗口里没有新请求、没有新截图），攒进 `data/learn.json`；
  **每一眼都喂一遍**（`worker._feed_learning`，OCR 有指纹缓存，画面不动就不重算）——
  原来只挂在「该吐槽的那一帧」上，限速一拦，一大半字幕其实没进档案。
* **边看边消化**（`learn.auto_promote`，默认开）：攒够格的接话对（问→答 见过 2 次）
  自己写进 `data/chat_style.json`，写前备份 `.bak`，写完 `humanstyle.reload()` ——
  **不用重启，它下一句话就用上了**。为什么默认开：只采集不消化，档案会顶到
  `max_lines` / `max_candidates` 的天花板，之后**新读到的反而是被丢掉的**（池满丢最低频 / 最旧的一批）
  ——现场就是这么攒了 2117 次观察、0 段进语料。自动消化只收**问→答**那一批（可信），
  非问答的照旧攒着，想收就 `python -m pet.corpus apply`。
  两个文件都在本机，随时可删。
* **主动夸 / 主动关心**（`proactive.content_nudge`）：判断"你现在在干嘛"这一步是**纯本地**的
  （窗口标题 + 已经认出来的游戏名 + 看片笔记，不额外截图、不发请求）；夸 / 关心那两句
  跟主动搭话走同一条通道（每小时有上限、有冷却），没配 Key 就退回本地台词。
  不想让它自己开口：`content_nudge = false`，或者直接关 `proactive.enabled`。
* **你诉苦时的安慰**：`humanstyle.needs_comfort` 只在本机拿几个词比一下你的输入
  （不打分、不留痕、不额外请求）；那一轮的提示词只多一段"别讲道理、抱抱他"。
* **整集资料卡**（`episode`）：**默认关着**（`episode.enabled = false`）。打开之后才会：认出画面上的字
  （节目名/季/集，判断在本机做）→ 多一次**纯文本**调用（不发图）问"这一集讲了什么"→ 答案存本机
  `episodes.json`，而且**同一集只问一次**。模型如果说不知道，就什么都不存。
  注意：它**不会**去下载或播放整集视频。
* **气泡里只会出现"说给你听的话"**：提示词块头（「画面关键信息」「你记得的事」…）、
  看片笔记、整集资料卡这些**内部信息一律不进气泡**——解析层有一道闸
  （`humanstyle.looks_like_internal`）会先剥掉开头的块头，还夹带内部字眼的整句丢弃并当场重要一句。
* **抓来的标题也不算话**（`humanstyle.looks_like_title`）：现场气泡里摆出过整条
  `《复仇者联盟3》剧情设定细节探案幕后解读`——页面上那支视频的标题，它照着念了一遍。
  这种句子一个「内部字眼」都不带（所以上面那道块头闸认不出它），「念屏幕」那道闸又要
  先剥掉块头才生效，于是整条漏进了气泡。判据是**标题特征 + 没有说话口气**：书名号里的
  作品名、话题标签、标题噪声词（万字深拆 · 幕后解读 · 剧情设定 · 完整版 · 第X期…）、
  尾巴上的括号补充；一旦句子里有问号感叹号或者「我你咱真太别不了」这种口气词就是
  **在说话**，照说不误。隐身学习那边同一个判据也挡着：标题不进语料、不进记忆。
* **"念屏幕"也算内部信息**（`humanstyle.looks_like_screen_echo`）：现场抓到过一句
  `画面关键信息：第孬期 . / > 0 收/A《抖音 ×/ 第集：`——它把 OCR 碎片拼了一串、还带着块头名，
  直接摆到你脸上了。这种句子不是逗号顿号分的标签，光比"整行是不是某一行的复制"抓不住，
  所以换成按**字**比：剥掉块头之后，这一句里**每个字画面上都有**（去标点后至少 6 个字、
  覆盖率 ≥ 80%）就判成"念屏幕"，整句丢掉、当场再要一句。
  提示词的输出格式里也把形状写死了：台词不许以块头名（「画面关键信息」「【现在】」…）开头，
  也不许把屏幕上的字/数字/符号拼成一串念出来——想提就说人话（"这集都第28集了"）。
* 每帧约 720px 宽的 JPEG（一般 40~90KB），按 `glm-4v-flash` 这类小模型的
  价格，长时间挂着一天通常也就几分钱到几毛钱；画像总结每半小时才一次，可以忽略。
* 抓屏时如果挂件恰好压在观看区域上，它会先把自己藏起来再拍，不会把自己的
  脸拍到画面里喂给模型。

## 看准，然后说人话

这两件事都写在 `pet/persona.py` 的提示词里，改这一个文件就能换性格和说话方式。

**说人话**：说话标准是「像微信语音转文字」——短句、带语气词、想到哪说到哪；
提示词里列了一串**禁用词**（值得一提 / 由此可见 / 展现了 / 总的来说 / 氛围感 / 首先其次……
出现就算说错），还给了反面例子和正面例子对着看，并要求别总结画面、别解释自己看到了什么。
模型的最终输出还会再过一个 `deformalize()` 兜底表（把漏出来的「此外 / 非常 / 令人 / 我认为」
这类词就地换成大白话），所以就算模型偶尔犯书面腔，你看到的也不会太出戏。
想更收/更放：改 `persona.style`、`persona.max_chars`，或者直接写 `system_prompt` 覆盖整套人设。

**别写解说词**：把「谁和谁 + 站在/走进哪儿 + 手里拿着什么」串成一句完整描述、再补个
「似乎是在参加什么环节」的推测——那是导播在介绍画面，不是聊天。提示词里明令禁止，
但小模型嘴上答应手里照写，所以本地还有一道闸：`humanstyle.looks_like_narration()`
认出这种句子就**不让它进气泡**，并让 worker 当场再要一句（提示词压成「只回一句话、
只说你自己那一下的想法」）。两道闸合起来的效果是：宁可少说一句，也不给你念镜头说明书。

**先看准（5W1H）**：提示词要求它每轮先在脑子里过一遍
Who 谁 / What 什么 / When 何时 / Where 何地 / Why 为何，并且**只写真的看见或从画面文字里读到的**，
看不清就写「未知」，不许编。看完再决定说不说、说什么。

同一轮它必须回两行：

```
[无语] 这操作我真看不懂
场景：人物=黑衣男主播｜事件=连抽十次没出金色｜时间=深夜｜地点=抽卡直播间｜原因=想抽到当期角色
```

第二行不是给你看的，是给程序用的（`pet/scene.py` 负责拆）：

- 写进长期记忆，关键词打标签、生成"观众画像"都更准（"直播间""打boss"这类词能进记忆了）；
- 下一轮提示词里回喂给模型，所以同一个场景它不会车轱辘话重复三遍；
- 解析是容错的：场景行放第一行、和台词挤在一行、写成 `人=主播｜事=做饭｜地=厨房` 都认；
  实在拆不出来也只是"这轮没有场景"，绝不影响台词（也不会把"场景：…"当台词念出来）。
- **这五样东西只进日志和记忆，绝不进气泡**：AI 是"先在心里过一遍，再用一句人话说出来"，
  不是把「人物｜事件｜时间｜地点｜原因」摆到脸上。模型偶尔会把**格式清单**当内容交上来
  （现场真出过气泡里写着 `这画面还挺酷的 / 场景：人物｜事件｜时间｜地点｜原因`），
  解析侧（`scene.py`）现在把这种骨架整个丢掉——它不是内容，是格式；
  一项都摘不出来时就算"这轮没看懂"，绝不硬编。
- 控制台会打印 `[scene] 人物=…｜事件=…`，想知道它到底看懂了什么，盯着日志就行。

**说人话**：除了"一句话、不超过 28 字"，提示词里还写死了几条：

- 大白话、短句、带语气词（诶 / 啊 / 哈 / 嚯 / 我服了 / 行吧 / 你别说）；
- 禁用书面腔和解说腔（「值得一提」「由此可见」「展现了」「总的来说」「氛围感拉满」…一个都不许出现）；
- 不许排比、不许四字词堆叠、不许报菜名式罗列，一次只抛一个点；
- 别老用同一个开头（尤其别每句都「这」开头），也别每句都反问；
- **别按部就班地吐槽**：不要「先说看到什么 → 再给评价 → 最后总结」这种三段式，
  也别用「因为…所以…」「虽然…但是…」把逻辑铺得严严实实——真人说话是想到哪说到哪，
  前后不搭、说到一半拐弯、忽然跳到别的都正常（这一条是照着"太呆板、没有生气"的反馈加的）；
- **心里想的和说出口的，不必是一回事**：第二行那个场景是留给程序归档的，
  第一行不需要跟它对得上，也不用为了照顾它把话写完整；
- **有情绪就先出声**：先「我服了」「不是吧」「好家伙」再补事，或者干脆只出声不补事
  （先摆事实再表态，是最像机器的写法）；
- 还给了几个"该有的说话样子"当样例：「哈哈这也能行」「我服了，他认真的？」「诶这波稳了」。

**气泡里的标点**（`persona.tidy_marks()`，最后一道手）：

| 规则 | 说明 |
| --- | --- |
| **只留 `，。？！…`** | 引用用 `“”`、书名号用 `《》`；比划动作的 `（抱住你）` 和表情符号（`❤`）也留着 |
| **不许出现 `「/」`** | 模型拿不定主意时会把两三句**备选台词**并列着交上来（现场那条：`这波稳了 / 这画面，高启强这表情，感觉他要发火了！ / 你得服从指挥吧你得接受`），屏幕上就是一串「A / B / C」。**一律在「/」处断开，只念第一句** |
| 别的符号全清 | `~ ～ ｜ # * — · 、 ； ：` 这些零散符号直接删；半角的 `, ? !` 归一成中文写法；`...` / `。。。` 统一成 `…` |
| 说完就停 | 提示词里另加了两条：不许把同一句话换几个说法摆出来、不许在末尾补「总的来说」式总结 |
| **太长就在句读处断** | `persona.fit()` 按最近的 `，。？！…` 断开，绝不让句子从中间被劈开（气泡里读着才不别扭） |

句首那个 `[情绪]` 标签不归它管——那是 `mood.split_mood()` 要剥的，清标点时会原样端过去。

长度上限是 `persona.max_chars`，性格是 `persona.style`，想换语气直接改这两个值。

## 边看边学（把字幕变成语料）

`data/chat_style.json` 那个语料文件一直是"给人往里贴聊天记录用的"，
只是没人替它贴。`pet/corpus.py` 就是**替它贴**：挂件每一眼 OCR 出来的字幕/台词，
过了闸门就攒成「上一句 → 下一句」的接话样本，够格了自己写进语料，
然后 `humanstyle.reload()` —— **不用重启，它下一次说话就用上了**。

**它到底"学"的是什么**（别想成训练模型）：语料是拼提示词时**当示范抽两条塞进去**的
（`humanstyle.sample_dialogue`），所以语料一变，说话方式当场变。不花钱、不联网、不改权重。
这正是"你贴一段聊天记录它就照着学"的那条老路，只是改成它自己一边看一边贴。

**三道闸**——OCR 读出来的东西大半是垃圾，没闸门等于往语料里倒垃圾：

| 闸 | 挡掉什么 |
| --- | --- |
| 像不像人话（`corpus.looks_like_speech`） | 太短/太长、时间码、「第25集」、UI 按钮词（已关注/取消收藏/不感兴趣…）、台标平台名、**评论区的界面文字**（`@用户名 4 天前`、`# 话题 #`）、解说腔（`humanstyle.looks_like_narration`）、书面腔（`banned`）、**读歪的界面文字**（成对的半角 `[ ] { } < >` 或错字「囗」——现场真混进来过 `杰可在 [ 设首 ] 里关闭或打开局内肯包中 3 囗色展示`），以及**中英数字掺半的 OCR 碎片**——按"中文占比 ≥ 50%"卡（`MIN_CJK_RATIO`）。这一条是**照现场日志补的**：头一版闸门把 `@ 暗区刂 TenZ 一 Valorant Agnes`、`1 57 封耒读 〕 网易 “ 0 D 0418` 这种当台词收进去了；评论那两条也是（抖音评论每支视频都不一样，出现比例低，**比例式招牌闸抓不到**，只能按长相认） |
| 是不是"招牌"（`_is_furniture`） | 一直挂在屏幕上的字：标题、台标、按钮。判据只有**出现比例**——台词说一次就过去，招牌每帧都在，看过几眼之后比例就压过台词一大截。**认出来之后，之前误收的台词和它配出来的对会一起撤掉** |
| 够不够格（`ready_pairs`） | 攒着的相邻对要反复出现才收：**「上一句在问、下一句在答」见过 2 次**就算（解说类视频里没人提问，所以问答基本能确定是两个人在对话）；普通相邻两句可能都是同一个人在说，要 3 次 |

### 边看边消化（`learn.auto_promote`，默认开）

采集和消化是两件事，**默认都开着**：

| 动作 | 谁在做 | 什么时候 |
| --- | --- | --- |
| 采集 | `worker._feed_learning` → `corpus.observe` | **每一眼**（本地 OCR，指纹缓存过，画面不动不重算） |
| 消化 | `corpus.maybe_digest` → `corpus.apply` | 到点了就试一次（`learn.digest_interval_sec`，默认 300 秒）＋每 `promote_every` 次观察一次 |

**为什么必须默认开**：只采集不消化的话，`max_lines` / `max_candidates` 一到顶，
**新读到的东西反而是被丢掉的**（池满丢最低频 / 最旧的一批）——现场就是
观察 2117 次、台词池 400 句 / 接话对 200 对全满、**已进语料 0 段**。

自动消化比手动收得更严，两道收紧：

* **只收问→答那一批**（`corpus.auto_pairs`）：解说的视频里没人提问，能配上"问→答"的
  基本就是真有人在聊；非问答的相邻两句可能都是同一个人在念屏幕，照旧攒着等你点头
  （`python -m pet.corpus apply`）。
* **进语料的对从"还在攒的"里退休**（`corpus.retire_promoted`）：`max_candidates` 管的是
  "还在攒的"，不退休的话池子永远满着，新的一对接不进来。

语料那边同理：`max_dialogue`（默认 60 段）满了，`corpus._make_room` 会先把
**自己学进去的最旧一段**请出去腾位置——**用户手写的对话一句都不动**。

认"哪句是同一句"**只认字、不认标点和空格**（`_key`，存进语料和打印给人看的还是原话）。
这条也是照现场日志补的：同一句字幕 OCR 每帧读出来的标点都会变
（`作者声明：虚构演绎，仅供娱乐` / `作者声明 ． 虚构演绎，仅供娱乐`），按原文算的话——
招牌的数永远攒不到 3 次（认不出招牌）、同一行还会被当成"前后两句"自己跟自己配对、
"见过 2 次"这条够格线**在实际使用中根本够不着**（升格那条路等于白摆着）。

**怎么知道的**：`data/learn.json` 是它的学习档案（台词池 + 接话对 + 荣誉榜），当场可看：

```bat
python -m pet.corpus          :: 看报告：观察几次、攒了哪些对、哪几对够格了
python -m pet.corpus apply    :: 把够格的写进 data/chat_style.json（写前自动备份 .bak）
python -m pet.corpus reset    :: 清空学习档案（语料文件不动）
```

**默认自己消化**（`learn.auto_promote = true`）：攒够格的（问→答 见过 2 次）自己写进语料，
写前备份 `.bak`、写完当场生效。想让它老老实实只记不写：`learn.auto_promote = false`
（连老的 `learn.promote` 一起关掉）。不想学就 `--no-learn` / `learn.enabled = false`。

只动 `dialogue` 这一个键：`patterns`（聊天的做法：只给反应、改口、抬杠……）得靠人总结，
机器从两句字幕里总结不出来，硬写进去只会是车轱辘话。

⚠️ 它学的是**屏幕上谁说的话**，不是"真理"：短剧/对话类视频学得最准，
纯解说类视频多半只能学到腔调；OCR 认错的字也会照着学（所以自动消化只收问→答那一批，
另外还有一道"读歪的界面文字"闸）。想先看看再决定就 `python -m pet.corpus` 翻报告，
随时可以 `python -m pet.corpus reset` 清档案。
回退很简单：删掉 `data/learn.json`，语料文件旁边还留着 `chat_style.json.bak`。

⚠️ 还有一条现实预期：够格线是**同一对接话见过 2 次（问→答）/ 3 次（前后）**，
所以在**不停划走**的短视频流里攒得很慢——一支三秒的视频只出一两句话，划走就再也不见，
半天攒不出几对是正常的。连续剧、直播、会复看的片子才容易攒出来。
嫌慢就自己看报告挑几对贴进 `data/chat_style.json`（那本来就是给人贴的），
或者把 `learn.promote_min_hits` 调小——但调的越小越容易学到废话，先看报告再动。

## 把它换成你画的人物

默认形象是内置的矢量「黄豆」（蓝圆球 + 5 种情绪表情）。给一张图就能换成图片帧版本：

```bat
python tools\make_pet.py assets\source\pet_src.png
```

它会做五件事：

1. **抠背景**：图太小先自动放大（见下），然后从四条边取一圈像素猜出背景色，再用 floodfill
   **只删和画面边缘连通的背景**——所以人物内部的白色（眼白、白手套、白鞋）不会被一起挖掉；
   判定「像不像背景」还要过一道彩度闸（`--chroma`）：背景是有颜色的（米色/淡蓝…）而人物身上
   有白手套/白衬衫时，只比色差会把它们一起吃掉——实测那张 3D 小人的白手套和米色背景灰度差
   只有 3，正是靠这道闸保住的。边缘再柔化一下不留白毛；最后把零星碎块、背景上的闪光和水印
   （`--min-ratio`）抹掉。

   渲染图背景上那团**柔和的地面投影**由单独一条判定（`--shade`）处理：它的色相和背景**一模
   一样**、只是整体暗了一档（实测是背景 × 0.73~0.86），色差和彩度两道闸都认不出它（色差比
   容差大、彩度又"够有颜色"）。它唯一的破绽是**逐通道除以背景色之后三个比值几乎相等**
   （差值 0.015~0.042，而皮肤是 0.19~0.34、白手套 0.17），所以拿这个当判据就能只圈住背景
   自己的阴影。不清掉的话，上到深色桌面上就是脚下一块灰斑。

2. **裁边 + 缩放**：按内容边界裁切，等比缩放后居中放进 256×256 的透明画布（`--size` 可改）。
   顺手把人物身上**细到画不出来的裂缝**补掉（`--heal`）：抠图时背景会从耳缝、下巴缝里渗进去，
   只剩 1~4 像素宽的一条透明缝（抠得没错，那个缝在源图上确实是背景），可 256 的画布上这么细
   的缝根本画不出来，缩放时只会变成断面两侧的一圈脏边——在深色桌面上就是耳后那两道竖条，
   看着像戴了耳机。补法是把「左右（或上下）都被实心像素夹住、自己又细又透明」的缝用两侧颜色
   线性过渡填上。

   还有一小块背景**封闭在人物里面**，`--strict` 单独收拾：典型的是两腿之间那道缝（上头顶着裤子、
   两边是腿、底下两只鞋挨着，四周都是人物），floodfill 从画布边缘绕不进去，可它颜色就是背景
   色，留在画面上就是腿间一条亮条。所以再用**严格得多**的色差门槛（默认 12，主容差 26）扫一遍，
   没和边缘连通的就一并删掉；门槛这么严，人物身上的浅色（皮肤高光、牛仔布亮面）都过不了。
3. **找眼睛**：认出两只眼珠，抠成 `eye_layer.png` 单独一层，并把底图里的眼珠用**它外圈的颜色**
   糊掉；同时把每帧的身体变换矩阵写进 `eye_layer.json`。这样运行时眼珠能跟着鼠标转，
   身体上下浮动时也不会飘出眼眶（详见下面「眼睛跟着鼠标转」）。没找到就跳过这一步。
   顺带一提：3D 渲染缩到 256 之后眼白常常只剩一两个像素，所以这一步（和第 3.5 步）是**在
   放大 4 倍的画布上**做的，几何完全一致，找到的坐标再除回去。
4. **生成动效帧**：对同一张静图做仿射变换，按正弦相位生成 **12 帧**一套的循环——
   呼吸（横向鼓、纵向压）+ 上下浮动 + 轻微摇摆，说话时还会多抖一点。一共 7 套：
   `idle / talk` 加 5 种情绪（`happy / excited / speechless / curious / smirk`），
   运行时按当前情绪自动切换；帧里的动作就是最终看到的动作（渲染器不再另叠一层弹跳），
   一整套帧转完一圈的时长由 `ui.anim_period` 决定（默认 30 秒，看着像慢慢呼吸）。
   幅度由 `MOTIONS` 表定，现在**只留一点点起伏**：待机脚底上下约 3px、身高变化约 2px
   （256 画布，挂件上再 ×0.66）——"看得出在呼吸，但不觉得它在喘"。
5. 写进 `assets/pet/`（`idle_00.png … idle_11.png` 这种**补零**命名），**重启挂件后自动切换**。

好使不好使的时候：

- 背景没抠干净 → 调大 `--tol`（比如 40），或用 `--bg 255,255,255` 手动指定背景色；
- **脚下一团灰斑/灰影**（3D 渲染图常见的地面投影）→ 先看 `--shade`（默认 0.5）：它是「背景色
  被光暗掉」的那部分像素的判定门槛，含义是"暗到背景的多少倍还认"，调大（比如 0.7）更保守、
  调小（0.3）更狠；关掉用 `--shade 0`。要是那个投影本身比背景暗得更多（k < 0.3），它也会留下；
- **耳后/下巴出现一条虚线似的脏边**（抠图时背景从缝里渗进去留下的 1~4 像素透明缝）→
  看 `--heal`（默认 4，允许补的最大缝宽）；缝更宽就调大，不想动它就 `--heal 0`；
- **两腿之间/腋下留了一小块背景色**（那块背景被人物围起来了，floodfill 从画布边缘绕不进去）→
  看 `--strict`（默认 12，比主容差严格得多的色差门槛）；还留着就调大一点（比如 16），
  人物身上反而被啃出洞就调小（比如 8），不要这条就 `--strict 0`；
- 人物被吃掉一块 → 调小 `--tol`（比如 12）；如果是**白手套/白衣服**被啃，
  那是背景有颜色（米色、淡蓝…）而它俩太像，调大 `--chroma`（默认 0.55，含义是"候选像素的
  彩度至少要到背景彩度的这个比例"，0.8 更保守）；背景本来就是白/灰时这条不起作用，不用管；
- 手上是**很小的图**（截图、表情包）→ 不用管，它发现短边小于 160 会自动先放大到约 320
  再抠（LANCZOS + 轻锐化），比硬缩上去清楚；不想要就 `--no-upscale`，想指定倍数就 `--upscale 4`；
- 抠完边上还剩小黑点（截图边框、压缩噪点）→ 会自动抹掉小于 48 像素的碎块，
  看不顺眼可以调 `--min-blob 200`（更狠）或 `--min-blob 0`（不清理）；背景上的闪光、水印这类
  装饰由 `--min-ratio`（默认 0.02 = 本体的 2%）一起清掉——它们贴在图边上，不清干净会把
  内容框撑大、形象被迫缩小；
- 想看抠完什么样 → 加 `--cutout assets\source\cut.png` 存一张出来对比；
- 命令行会打印透明/实体占比：**透明太少**说明背景没删掉，一眼就能判断；
- 手上还没图，想先看动效 → `python tools\make_pet.py --demo`（画个占位形象，
  只写进 `assets\source\demo`；加 `--install` 才装进挂件）；
- 想退回内置矢量形象 → `python tools\make_pet.py --clear`。

帧的加载规则在 `pet/sprite.py`：`idle_*.png` 待机、`talk_*.png` 说话、`<情绪>_*.png` 对应情绪，
按**文件名末尾的数字**排序播放，所以帧数超过 9 张也不会排乱（建议像 `idle_00.png … idle_11.png` 那样补零，看着也整齐）。

别人不该为了用一只桌宠去装 Python。仓库里已经把这条路铺好了：

```bat
build.cmd                 :: 双击就行：装打包依赖 → 现画图标 → 打包
                          :: 出 dist\ScreenPet\ScreenPet.exe
python tools/build.py --zip     :: 顺手压成 dist\ScreenPet-<版本>.zip（发给别人就是这个）
python tools/build.py --onefile :: 想要"就一个 exe"（启动慢一点）
python tools/build.py --clean   :: 清掉 build\ 和 dist\ 重来
```

**打包之后程序怎么找文件**（这是最容易踩的坑，全写在 `pet/paths.py`）：

| | 源码里跑 | 打包成 exe 之后 |
| --- | --- | --- |
| 配置 / 记忆 / 语料 / 日志（**要写**） | 项目根目录（老位置，没变） | `%APPDATA%\ScreenPet\`（exe 装在 Program Files 里也写得进去） |
| 形象帧 / 默认配置 / OCR 脚本（**只读**） | 项目根目录 | exe 解包目录（`sys._MEIPASS`，打包时由 `--add-data` 带进去） |

第一次启动时会照着 `config.example.json` 生成一份 `config.json`，并且冒一句气泡告诉你
"右键我 → 打开配置文件"——不然用户根本不知道配置写到哪儿去了。
想固定在一个地方跑（U 盘 / 便携版）：设环境变量 `PET_HOME` 就行。

| 相关文件 | 干什么 |
| --- | --- |
| `tools/build.py` | 打包本体：素材清单、图标、版本信息、`--zip`、同步安装脚本版本号 |
| `build.cmd` | 给不爱敲命令的人：双击 → 装依赖 → 打包 |
| `tools/make_icon.py` | 现画 `assets/app.ico`（形象是矢量画的，所以图标得渲染一遍再交给 Pillow） |
| `installer/ScreenPet.iss` | Inno Setup 安装包（开始菜单 + 卸载项，可选；绿色版不需要） |
| `.github/workflows/build.yml` | 打 tag 自动：跑冒烟测试 → 打包 → 发 Release（别人在 Releases 直接下载） |
| `docs/打包发布.md` | 这一整套的来龙去脉 + 发布检查清单 |

## 隐身学习（收进托盘，自己上网补课）

你不需要它的时候，可以把它**收进托盘**：托盘图标点一下（或右键菜单里的「我先隐身」），
屏幕上就没它了。

收进托盘 = 「这会儿不用你」，所以那段时间它**不再拍你的屏幕**——人都走了，拍下来也没人
看，白花算力和接口钱。它换成干一件事：**自己上网学**（`pet/webstudy.py`）。这一条**默认开着**：
收进托盘就自己补课，**没有开关**（右键菜单里那个勾选项已经撤了）——不想花这份钱就在配置里
写 `"study": { "enabled": false }`，那它就纯歇着：

```
拿「他最近在看的那一支 / 那个游戏」当话头（worker._study_topics），
没有就用长期记忆里常看的（memory.topics / 常看的类型）
        ↓ 话头先精修：剥掉「第 11 期」「完整版」「- 哔哩哔哩」这类噪声；宽泛词往后排
搜一下（Bing → DuckDuckGo，谁通用谁），读前几页正文
        ↓ 一页算不算「料」看三条：够长、有中文、跟话头沾边（page_ok）——三条缺一不读
让模型整成两样东西（纯文本一次调用）
        ↓ 有网页材料时再核一遍：哪几句材料里真有依据（verify）——编的一律不要
  · 几句「接话」→ 写进 data/chat_style.json 的 dialogue（跟边看边学同一个出口，写完立刻生效）
  · 一个「知识点」→ 写进 memory.json（私下算「学习」那一类，见 ③）
        ↓
回到屏幕上时它先冒一句「我刚在后台查了查『…』」——你会知道它没闲着
```

守住四道闸（跟「边看边学」一个思路：网上抄来的东西大半是垃圾）：

| 闸门 | 干什么 |
| --- | --- |
| 正文 | 网页先剥 `script` / 样式 / 注释，块级标签换行，按 `study.page_chars` 截断 |
| **像不像料** | 正文短于 `study.min_page_chars`（默认 300 字）、中文占比太低、跟话头不沾边 → 这一页不读（搜索结果里一半是导航页 / 加载页 / 同名别的站，读进去就是让模型硬编） |
| 像不像人话 | 模型写回来的每一句都过 `corpus.looks_like_speech()`：书面腔、解说腔、界面词、半句全丢 |
| 不是客服腔 | 官网 FAQ 那种「有什么 X？→ 有 A、B 等。」一问一答一律不要（`webstudy.looks_like_faq`） |
| 标题不是料 | 搜回来的页面标题（`《复仇者联盟3》剧情设定细节探案幕后解读`）既不是「接话」也不是「知识点」——`humanstyle.looks_like_title` 在写语料 / 写记忆前先挡一道，免得学会了「念标题」，回头又把抓来的信息端给用户 |
| **有没有依据** | 有网页材料时再问一遍模型：候选里哪些在材料里能指出对应句子（`study.verify`，默认开）。材料里找不到的丢掉；它没照格式回就**原样收下**（白核一轮也好过把这一轮清零） |
| 别重复 | 语料里已有的段落用 `humanstyle.similarity` 比一遍（≥0.7 当同一段，不再塞） |
| 限量 | 一轮最多收 `study.max_rows` 段接话 + `study.max_notes` 条知识点（模型爱一口气写十几条） |

**另外两件让它学得更准的事**（都不额外花钱）：

- **补课单独用一个文本模型**：`study.model`（配 `study.base_url` / `study.provider`）填了就单开
  一份客户端——补课是纯文本活儿，用 `glm-4-flash` 这类文本模型比主配置那个视觉模型准得多、
  也便宜；屏幕那边照旧用视觉模型，两边互不影响（留空 = 跟主配置同一个）；
- **话头优先屏幕内容**：`worker._study_topics` 给的顺序是"他刚在看的那一支 → 台标/节目名/游戏名
  → 他反复看的词（`taste.hot_topics`，从他点过赞/收藏的内容里攒的）"，都挑不出来才轮到
  长期记忆里的类别词——类别词（"游戏""短视频"）搜回来的是同名杂志和官网，学到的全是垃圾（现场踩过）。
- **话头账本**：学过的话头记进 `study.ledger`（默认 `data/study.json`），
  `study.topic_cooldown_sec` 之内不再学（别老啃同一个梗）、老交白卷的排到最后——
  这样每轮的接口钱都花在新的、搜得动的话题上。

**联网不通**（国内搜索引擎经常打不开）时：`study.model_fallback=true`（默认）就直接拿话头
问模型本人——一样是「上网」、一样花钱，只是没有网页做依据；关掉它就这一轮什么都不写。
两种情况下它都**不会自己编内容往语料里塞**：模型没按格式回，这一轮就交白卷。

节奏由 `study.interval_sec`（默认半小时一轮）+ `study.max_per_hour`（默认一小时 2 轮）管着，
不会你回来一看接口账单被它刷爆。想单独看它学什么、为什么挑它、学成什么样：

```bat
python -m pet.webstudy --topics   :: 候选话头 + 会被怎么处理（不联网、不花钱）
python -m pet.webstudy --force    :: 不管开关、间隔和冷却，立刻学一轮
```

| 配置 | 作用 | 默认 |
| --- | --- | --- |
| `study.enabled` | 收进托盘时允不允许它自己上网学 | **开**（默认就学；没有开关，改 `false` 才歇着） |
| `study.interval_sec` / `study.max_per_hour` | 多久学一轮 / 一小时最多几轮 | `1800` 秒 / 2 轮 |
| `study.topics` / `study.topic_limit` | 固定学什么（留空 = 先用「他最近在看的那一支 / 那个游戏」，其次长期记忆）/ 一轮挑几个话头 | `[]` / 2 |
| `study.engine` | 搜索引擎：`auto` / `bing` / `duckduckgo` / `none`（只问模型） | `auto` |
| `study.results` / `study.page_chars` / `study.timeout` | 一个话头读几页 / 每页截多少字 / 网络超时 | 3 页 / 2400 字 / 12 秒 |
| `study.model` / `study.base_url` / `study.provider` | 补课专用模型（留空 = 跟主配置同一个） | 空 |
| `study.verify` | 有材料时让模型核一遍「这句有依据吗」 | 开 |
| `study.min_page_chars` / `study.min_page_match` | 正文至少多少字 / 至少命中几个「话头两字词」才算料（0 = 不查） | 300 / 1 |
| `study.block_hosts` | 不想让它读的站（子串匹配，比如 `"csdn.net"`） | `[]` |
| `study.topic_cooldown_sec` / `study.fail_penalty` | 同一话头多久内不再学 / 白卷几次之后排最后 | `21600` 秒 / 3 次 |
| `study.ledger` | 话题账本放哪儿 | `data/study.json` |
| `study.model_fallback` | 搜不到时允不允许只问模型 | 开 |
| `study.max_dialogue` | 语料里 `dialogue` 最多留几段 | 60（跟 `learn.max_dialogue` 一致） |
| `study.max_rows` / `study.max_notes` | 一轮最多收几段接话 / 几条知识点 | 3 段 / 2 条 |

**⑧ 只盯某个程序（抖音 / B站 / 游戏 / 浏览器）**

不想让它"整屏到处看"，只想让它盯着一支视频时用这个：右键我 →「只盯着一个程序（抖音 / B站 / 游戏）…」，
点开来列的都是眼下看得见的程序，选一个就锁上。

| 行为 | 说明 |
| --- | --- |
| 拍哪块 | 只拍那个窗口的**内容区**（不含标题栏和边框）；窗口被拖动、缩放、最大化都自动跟上 |
| 认哪个窗口 | 只按 **exe 名**认（比如 `chrome.exe`），所以视频标题变了照样跟得住；同一个 exe 开了好几个窗口时，取前台那个、其次是面积最大的那个 |
| 你切去干别的了 | **默认照样盯着**（`target_foreground_only = false`）：它不走 mss 拍屏幕，而是直接让那个窗口把自己画一遍（`pet/wincap.py` 的 PrintWindow），所以窗口被别的窗口盖住也看得到。想改成"切走就别打扰"，把 `capture.target_foreground_only` 设回 `true` |
| 它被最小化 | **照样盯着**：最小化时 Windows 不给它画新画面（实测浏览器交回来的是全黑、Tk/GDI 交回来的只有标题栏三个按钮），所以这一路先按「还原尺寸」问一句它能不能画，画得出来就照看，画不出来就**回放最后一眼**——它还"记得你看到哪儿了"，你问它在看什么照样答得上来，只是不会再拿旧画面编新词（也不吸收、不花接口钱）。托盘那行会写「收起来了，我按最后一眼陪着」，提醒只说一遍（不再每 90 秒念一次） |
| 它被关掉 | 找不到窗口就不抓屏、不花钱，偶尔提醒一句"没找到窗口"（90 秒最多一次），你打开它自己接着看 |
| 状态在哪看 | 鼠标停在托盘图标上，提示里会写「监视范围：只盯 chrome.exe（正在看 / 收起来了，我按最后一眼陪着 / 没找到窗口 / 切到后台了）」；右键菜单里则勾在「只盯着一个程序：chrome.exe」那一项上 |

相关配置（`config.json`）：

| 键 | 默认 | 意思 |
| --- | --- | --- |
| `capture.target_process` | `""` | 只盯这个 exe（`Douyin.exe` / `chrome.exe` / `Tabbit Browser.exe`…）；留空 = 关掉这个能力 |
| `capture.target_title` | `""` | 可选：再按窗口标题关键字筛一道（同一个 exe 有好几个窗口时用得上） |
| `capture.target_foreground_only` | `false` | `false` = 你切去干别的它照样看（推荐）；`true` = 只有它在前台时才看（切走就不打扰、也不花钱） |
| `capture.target_client_area` | `true` | 只拍内容区，不拍标题栏和边框 |
| `capture.window_capture` | `true` | 不在前台时直接抓窗口自己的画面（被盖住也能看）；抓不到才退回拍屏幕 |

命令行也行：`python -m pet.app --target-process "chrome.exe"`（只在这次运行生效，不写进配置），
`--no-target-process` 取消锁定。锁定之后原来框选的那块会自动清掉——两套规则叠在一起只会让人
搞不清它到底在看哪块。别把它和"鼠标穿透"搞混——「把我钉在这儿（鼠标点不到我）」（右键 →「我自己的事」）
锁的是"挂件挡不挡鼠标"，跟"看哪块"没关系。

实现上就是纯 `ctypes` 枚举顶层窗口（`pet/winfind.py`）：不装依赖、不读别人的进程内存，
只问 Windows「这个窗口叫什么、属于哪个 exe、内容区在屏幕上的哪一块」。拿到的矩形已经是物理像素
（和 mss 抓屏同一个坐标系），所以 125% 缩放的屏上也不会偏。

抓画面分两条路：**它在前台**走 mss 直接拍屏幕（最快，视频层一起拍下来）；**它不在前台**就走
`pet/wincap.py` 的 `PrintWindow`——让窗口把自己画一遍到离屏位图上，所以被别的窗口盖住也照样看得到。
少数用独占全屏 / 硬件覆盖层的播放器只会给出一张黑图，这种情况我们自己认出来并如实报错，
不会拿黑图去糊弄模型。

**⑨ 说话像人（口语语料 + 反车轱辘话）**

原来它很容易变复读机：同一个画面、同一个模型、翻来覆去就是「这操作我真看不懂」
（`memory.json` 里能看到同一句话连着刷十几条）。现在有两道闸 + 一套语料：

- **每轮换一个"说话角度"**：从三十**六**种真人做法里随机挑一条塞进提示词——只给反应、半句、改口、
  抬杠、自曝、算账、跑题、阴阳、打赌、催、复读加料、盯细节、学人说话、拉回现实、只丢一个词、
  先问后答，外加照真实聊天记录拆出来的一批：只接对方最后一句、反问求证、拆术语、共鸣换伤、
  安慰带办法、拿自己举例、承认不知道、顺手换台、短句连发、同意再补、一句话收尾、报生活流水、
  夸张量词、不客气、追一个细节，还有专门对付"太呆板"的四个：想一出是一出、不接逻辑、
  顺嘴联想、半路放弃——再随机附两段真人式对话例句（共 22 段）和一把语气词，
  所以同一帧画面对应的话不会总是同一个味道。
- **不写"文案腔"**：提示词里明确禁掉「值得一提 / 由此可见 / 氛围感 / 仪式感 / 赋能 / 闭环…」这类词，
  说出口之前还有最后一道手（`persona.deformalize()`）替换掉漏网的书面词，并去掉句尾那个句号
  （微信里没人打句号）。
- **不许把提示词当台词**：小模型偶尔会把提示词里的说明句（「如果画面基本还是同一件事，就别重复…」）、
  块头（「【你刚才说过】」）、记忆行整行抄回来——这种句子出现在气泡里，最像是"它坏了"。
  现在有两道手：解析层把"整行只是个短括号短语"当块头丢掉（`scene._HEADER_ONLY`），
  VLM 层再把候选台词和刚发出去的那份提示词**逐行比对**，是抄的就整句丢掉（`humanstyle.looks_like_echo`）。
- **反车轱辘话（两道闸）**：worker 记着最近说过的 16 句（吐槽 + 对话 + 搭话都算），新句子如果跟
  它们像到 0.62 以上（按字符二元组算 Jaccard 相似度，所以「这操作我真看不懂」和「这操作我真看不懂啊」
  会被认定成同一句），就**先要求它换个说法重说一次**；这次再重复就干脆闭嘴。对话那一路必须回你，
  所以是从两次里挑更像"没重复过的"那句，不会把你晾着。离线 `mock` 模式不做这个判断——
  那套台词本来就只有几句，否则演示两轮它就哑了。

**语料可以换成你自己的**：编辑 `data/chat_style.json`，把聊天记录整段贴进 `dialogue`
（一段一组，或者一行用 `|` 分成几句），重启挂件之后它就照着你的说话方式学；
`patterns / openers / enders / fillers / banned` 也都能往里加。删掉这个文件也能跑（用内置语料）。

> 说明：语料是**离线内置**的——最早整理的是"真人聊天到底怎么接话"这件事本身（短句、半句、改口、
> 跑题、语气词、熟人之间的挖苦），后来又照着一份真实的微信聊天记录补了一批（只接对方最后一句、
> 反问求证、共鸣换伤、承认不知道、一句话收尾……），并且把"客服腔"（亲 / 您好 / 请问 / 感谢）
> 也加进了禁用词。想让它更像你，最直接的办法就是把 `data/chat_style.json` 换成你和朋友的聊天记录。

**⑩ 真的看得懂在放什么（连拍 + 定期重读）**

只给一张静图，模型只能认出"这是什么画面"，认不出"在演什么"——综艺到了哪个环节、剧情讲到哪、
游戏里刚打完哪一波，都要靠前后对比才看得出来。所以这一轮专门补了这几件事：

| 做法 | 为什么 |
| --- | --- |
| **一次给 3 张连拍**（`capture.seq_frames`） | 把最近三眼横向拼成一张"分镜图"（`capture.sequence_sheet`）再送出去：接口那边仍然只花一张图的 token，但模型能看出**在发生什么**（提示词里会写明"从左到右按时间排"） |
| **分辨率提到 1280 宽**（`capture.max_width`） | 原来 720 宽，字幕、弹幕、界面上的小字基本糊成一团；现在标题和台词都读得清 |
| **窗口标题按"被盯的那个窗口"取** | 以前给模型的是"当前前台窗口"的标题（你一走它就报 VS Code）；现在是「《歌手》第 8 期 · 哔哩哔哩」这种——认内容最便宜的线索 |
| **同一支视频每 75 秒重读一遍**（`capture.absorb_refresh_sec`） | 原来只在换视频那一瞬间读一次，长视频越看越对不上；现在会带着上一遍的笔记重读、把笔记更新掉（`watchlog.refresh`），而且这一步只记不说话 |
| **进度往前走一段就再读一遍**（`capture.absorb_progress_step`） | 时间那条不管内容，你拖一下进度条它就过期了。现在**跟着进度**走：每前进 10%（可调）重读一遍，前面 20%、中间 50%、后面 70% 分别读到什么全攒着（`worker._viewing_block()`），所以它说的话扣在**你正看到的地方** |
| **画面上的字优先** | OCR 出来的标题/字幕/弹幕连同"先读画面上的字再开口"一起进提示词；5W1H 里还多问一句"**这到底是什么内容**、谁在跟谁说什么、前后是什么逻辑" |

结果就是它的话能扣在具体内容上（谁说了什么、接下来大概会怎样），而不是只讲颜色、氛围和"这画面"。

**⑪ 越看越懂你：自己训练自己的口味（分类 → 看你反应 → 调劲儿）**

这一步是照着抖音那类"群聊小助手"的路子做的：**先给内容分类，再看你怎么反应，最后按反应调整说话的劲儿**。

| 做法 | 怎么做的 |
| --- | --- |
| **每支视频记一条档案**（`pet/taste.py` → `taste.json`） | 换视频时看片笔记顺手给出**类型**（游戏 / 影视综艺 / 剧情解说 / 搞笑 / 音乐舞蹈 / 知识科普 / 生活日常 / 美食 / 体育 / 宠物 / 汽车房产 / 新闻财经 / 带货直播 / 其他）+ 主题 / 内容 / 看点 / 人物 / 关键词 |
| **看你怎么反应**（互动信号） | 两路：① 看片笔记那一轮顺便看右侧按钮（点赞 / 收藏 / 关注 / 评论亮不亮、有没有「已关注」）；② OCR 扫画面文字里的「已关注」「已收藏」当免费兜底 |
| **算兴趣分，不靠猜** | 关注 +5、收藏 +4、点赞 +3、评论 +3、看完 +2、看得久 +1、秒划走 −2；再按类型聚合出"他真爱看什么" |
| **调说话的劲儿** | 最近 20 支平均分为正 → `warm`（多接话、一起起哄）；为负 → `cool`（少开口、别硬夸）。这一档会写进提示词，同时通过**劲头系数**（`nudge_scale` 0.6 / 1.0 / 1.6）直接乘到主动搭话的冷却上：越对他胃口，越愿意多陪两句 |
| **当场有反应** | 换视频读完笔记 → **立刻接一句**；看到你点赞/收藏/关注 → **当场说一句**（`watch.speak_on_new_video` / `watch.react_to_actions`）。模型万一没接上，就退到一句短反应（「就这？」「哈哈」），不冷场 |

攒够 3 支以上，它就会在提示词里带上自己写的一段「你摸清的他的口味」，例如：
「看得最多：游戏（12 支）｜会主动点赞收藏的：游戏（3 支，平均 +4.3）｜基本划走的：搞笑（平均 −1.0）｜
他反复看的：「王者荣耀」「KPL」｜现在该用什么劲儿：他最近看得挺来劲，跟着一起起哄」。
这些都是本地文件，删掉 `taste.json` 就等于把它的口味记忆清零。

**⑫ 跟着你的进度看（"正在看的那部分"是一段段读完的）**

原本的思路是"整集资料卡"：认出是哪一集就去弄清楚整集讲了什么。可原片是**扒不到**的
（视频源、登录态、流量、版权，一条都绕不过），问一句模型的印象终究只是印象。

所以主线换成了**盯着你正在看的这一段**：

| 做法 | 怎么做的 |
| --- | --- |
| **本地量进度**（`pet/progress.py`，免费） | 每眼看一眼底部进度条，记下这支视频见过的**最大**进度（播到头时进度条会被重播画面盖掉，所以记最大值最稳）。认不出来就什么都不做，绝不误判 |
| **进度走一段就重读一遍**（`capture.absorb_progress_step` 默认 0.1） | 你在 10% 和 在 60% 看到的是**两段内容**，只拿开头那份笔记应付，说起来永远是开头那点事。每前进 10% 就重读一次（`absorb_progress_min_gap_sec` 默认 20 秒内不重复读，防拖进度条时连读） |
| **攒成"他这支看到哪了"**（`worker._viewing_block()`） | 每段留一条短记录（最多 8 条）+「他这支已经看到 62% 了」，一起进提示词。所以它能说"你前面不是还说他俩不熟吗"，也不会把**还没演到**的当剧透说出来 |
| **整集资料卡退回可选** | `episode.enabled` **默认关**——想要"提前知道整集背景"再手动打开，不再默认花那一次调用 |

顺带把现场那个"漏内部信息"的问题也堵死了：气泡里出现过
`画面关键信息：第孬期 . / > 0 收/A《抖音 ×/ 第集：`——它把 OCR 碎片拼了一串摆到你脸上。
这类句子不是逗号顿号分的标签，比对"整行是不是提示词某一行"抓不住，所以换成按**字**比
（`humanstyle.looks_like_screen_echo`）：剥掉块头之后，**这句里每个字画面上都有**
（去标点至少 6 字、覆盖率 ≥ 80%）就判成"念屏幕"，整句丢掉、当场再要一句；
提示词的输出格式里也写死了不许以块头名开头、不许把屏幕上的字/数字/符号拼一串念出来。

## 形象动画：呼吸要连贯，不能闪

前几版的呼吸"一直在闪、看着累"，根子在三个地方，现在都改掉了：

| 原来的问题 | 现在怎么做 |
| --- | --- |
| 帧率写死 8fps 硬切帧，等于**一秒喘一口气** | 改成按"呼吸周期"走：`ui.anim_period`（默认 30 秒一轮，慢到几乎看不出它在动）决定一整套帧转完一圈要多久，情绪再按比例加快/放慢（激动快、无语慢、说话时快一半） |
| 相邻两张之间**硬切**，8 帧就看出顿挫 | **交叉淡化**：始终在相邻两帧之间做透明度过渡，12 帧也能走出连续的呼吸感（`ui.anim_crossfade = false` 可以关掉） |
| 每帧都在**重新缩放**图片 + 按亚像素位置绘制，125% 缩放的屏上必然抖 | 缩放结果按"哪套帧 / 第几张 / 目标尺寸"**缓存**，并且把落点**对齐到整数设备像素**，一帧只算一次 |
| `make_pet.py` 帧里已经带了弹跳，`sprite.py` 又叠一层程序化弹跳，两个周期互相打架 | 去掉重复的那一层：帧里的动作就是最终看到的动作 |
| 人物画满画布，被**圆形**遮罩切成直边（脚和身体两侧一半没了） | 装帧时统一裁边 + 缩放：按"内容外接矩形的角刚好落在圆上"算比例，瘦长的人物画得尽量大、矮胖的自动收一点，圆外像素保证是 0（`FRAME_SAFE` / `FRAME_MAX_ZOOM` 在 `sprite.py`） |
| 呼吸幅度太大：待机脚底上下 **10px**、身高变化 **9px**，挂在桌边像一直在喘 | 幅度收到"肉眼范围内一点起伏"（`MOTIONS` 表：待机脚底 ~3px / 身高 ~2px，256 画布；挂件上再 ×0.66）。情绪那几套保留弹跳（那是表情不是呼吸），呼吸分量和待机同一量级；内置矢量「黄豆」的呼吸同步收到约 1/2.5 |

帧数也从每套 8 张提到 **12 张**（`tools/make_pet.py` 默认值），文件名补零到两位
（`idle_00.png … idle_11.png`），渲染器按末尾数字排序，所以超过 9 帧也不会排乱。
想要更顺可以 `--frames 20`；动作幅度想调就去 `tools/make_pet.py` 里的 `MOTIONS` 表
（**改完要重新跑一遍 `make_pet.py`**：帧里的动作就是最终看到的动作，光改表不重新生成是不生效的）。

```bat
python tools\make_pet.py assets\source\pet_src.png --frames 16   :: 更顺一点
```

## 日常状态和界面互动动作

`assets/pet/` 里的帧分两拨：**串门那 7 套**是两只凑一起才做的（见「好友系统」那节），
**日常状态那 18 条**是它自己待着的样子、以及你在本机跟它互动时的小反应（`pet/states.py`）：

| 什么时候 | 切成哪条状态 | 怎么播 |
| --- | --- | --- |
| 平时 | 待机 / 说话 | 一直循环（就是呼吸那一套基础帧） |
| 双击暂停 | 睡觉 | 一直循环 |
| 麦克风开着、在听你说 | 张望 | 一直循环 |
| 它在等你那句话从模型那边回来 | 想事情 | 一直循环 |
| 你正把它拖到别的地方 | 走路 | 一直循环 |
| 你把鼠标停在它身上一会儿 | 挥挥手 | 播一遍就停 |
| **左键点它一下** | 从动作池里**随机**演一个（见下表） | 播一遍就停 |
| 你双击它一下 | 被戳（同时暂停 / 继续看） | 播一遍就停 |
| 你把它拖起来又放下 | 蹦一下 | 播一遍就停 |
| 抓到的画面是什么情绪 | 见下表 | 播一遍就停 |

动作有三个触发口子，都写在 `pet/states.py` 的表里，互相不打扰：

* `STATES`：**它现在什么情况** → 一直循环的日常样子（上表前四行）；
* `REACTIONS`：**你在界面上做了什么** → 播一遍（鼠标悬停 → 挥挥手、双击 → `poke` 被戳、
  拖完放下 → `jump` 蹦一下）；
* `CLICK_ACTIONS`：**左键点一下演哪个** → 随机池（下面那张表就是池子）；
* `MOOD_ACTIONS`：**抓到的画面表达什么情绪** → 顺手带上一个动作，情绪见 `pet/mood.py`：

| 画面情绪 | 动作 | 画面情绪 | 动作 |
| --- | --- | --- | --- |
| 开心 / 激动 | 欢呼 `cheer` | 无语 / 生气 | 摇摇头 `shake` |
| 惊讶 | 被戳般惊跳 `poke` | 难过 | 坐下 `sit` |
| 好奇 | 疑惑 `confused` | 吐槽 | 摸鱼 `slack` |

情绪本来就只驱动表情和气泡配色（不上界面），现在**顺手多带一个动作**：同一句话说完，
它就做一个对应的样子。正做着动作的时候不打断（一串吐槽连着来，总得让人家演完一个）。

**想让它演哪个动作？点它一下就随机来一个**——这些动作以前单列在右键菜单的「逗它一下」
那一节里，得进菜单一项项挑；现在**左键点一下挂件**就从池子里随机演一个
（`pet/states.py` 的 `CLICK_ACTIONS`，同一个动作不会连着演两次）：

| 池子里的 | 演的 | 池子里的 | 演的 |
| --- | --- | --- | --- |
| 挥挥手 | 挥手 `wave` | 被戳般惊跳 | 被戳 `poke` |
| 抬手打个招呼 | 打招呼 `greet` | 蹦一个 | 蹦一下 `jump` |
| 高兴一下 | 欢呼 `cheer` | 喂它一口 | 吃饭 `eat` |
| 点点头 | 点头 `nod` | 摸会儿鱼 | 摸鱼 `slack` |
| 摇摇头 | 摇头 `shake` | 伸个懒腰 | 伸懒腰 `stretch` |
| 歪头疑惑 | 疑惑 `confused` |  |  |

池子里不放"只有特定场合才合适"的动作（坐下 / 睡觉那两条）——点它一下不该把它按到地上。

全是本机动作：不联网、不进提示词、也不打扰它正在看的东西。鼠标那几下同理——
停在它身上 0.9 秒它会跟你**挥挥手**（25 秒内不重复，手一抖不会挥个不停），
把它拖起来再放下它会**落地蹦一下**。`agree` → 点头、`deny` → 摇头这两个键
对话 / 好友那边应答也走同一个。

- 状态名就是帧名前缀（`walk_00.png … walk_11.png`），加载规则跟 `idle_*` / 串门动作完全一样，
  想换成手画的直接覆盖同名文件。
- 「一直循环」的转完一轮多久，由 `pet/states.py` 里那条状态的 `seconds` 决定；「播一遍」的
  放完会自动回落到待机 / 说话。两条路走的是同一套接口（`PetWindow.set_pose` / `react` / `play_mood`）。
- 哪条没放帧都不崩：循环的状态老实退回待机 / 说话，一次性的互动退回「蹦一下」
  （`sprite.act_lift`）——少放几套绝不会崩。
- 这些状态**各有一套自己的动作**，不是"同一套呼吸换层皮"，而且分两层：
  1. **整张图一起摆**——`pet/states.py` 里逐拍写**手写关键帧**（`keys`：`dx/dy` 位移、
     `scale` 缩放、`squash` 压扁、`tilt` 旋转，`keys_loop` 说明是"转一圈"还是"播一遍"），
     `make_pet.py` 再插值采成 12 帧；走路左右脚交替就是这么来的。没写 `keys` 的那几条
     照旧用原来那套正弦抖法，两条路并存。
  2. **逐部件摆**（`rig_keys`）——**这才是"真的在点头 / 在挥手"**：头绕脖子（往下沉 = 点头、
     左右转 = 摇头、转个角度 = 歪头）、手臂绕肩（往外侧抬起来 = 挥手 / 欢呼）。
     每拍给整体那套参数 + `head` / `arm` 两层，生成时 `make_pet.py` 把形象拆成
     **躯干 / 头 / 手臂**三块各自转（挖走部件留下的洞按旁边的颜色补上）。
     所以点头是头在点、身子不动，挥手是手绕肩抬起来——不是整个人一起抖。
     部件位置（脖子 / 肩 / 掩膜）在 `make_pet.py` 顶上的 `RIG_*`，全是画布比例，
     照当前这个形象量的；换了一张完全不同的图、切歪了，生成时加 `--no-rig`，
     动作自动退回上面第 1 种，一帧都不会崩。
  走路是左右脚交替、被戳是缩团→惊跳→落地、吃饭是低头去够一口→鼓腮嚼→拍肚子……
- 有些帧上还画了一个小提示符号（疑惑的 `?`、被戳的 `!`、打招呼的星星、生气的怒气、
  难过的汗滴）——**一个字都不上界面**，只是让动作更好读；符号画在姿势摆好之后，
  不跟着身体一起被拉扁。
- 这批帧也是 `tools/make_pet.py` 一起生成的（各 12 帧），所以**改完同样要重新跑一遍
  `make_pet.py`** 才生效。想自己编排动作，就在 `states.py` 的 `Pose(...)` 里加 `keys=(...)`
  （整张图）或 `rig_keys=(...)`（逐部件，头 / 手臂）。

## 已知限制 / 注意

* **混合缩放的多个显示器**：区域框选按"矩形所在屏幕的缩放比"换算，绝大多数
  情况正确；如果两块屏缩放比不同且区域横跨两台屏，请分屏框选。
* **全屏独占的游戏**（DirectX 独占模式）用普通截屏可能抓到黑屏，
  建议把游戏改成"无边框窗口"模式。
* **改配置文件要先退出挂件**：挂件退出时会把内存里的整份配置写回 `config.json`。
  如果你开着它改文件（尤其是填 Key），退出那一刻会被旧值覆盖。填 Key 用
  `set-key.cmd --restart`，或者先从右键菜单里退出（「我先走了（退出）」）再改。
* 检测到的画面变化是"整幅画面对比"，镜头快速切换的视频会经常触发调用，
  把 `change_threshold` 调大一些（比如 0.08）可以让它安静点。
* **OCR 的准确性**：Windows 自带引擎对"小而花的字"（比如滚动的弹幕）识别一般，
  想把弹幕看清就单独框选弹幕那一条；想要更准可以装 `rapidocr-onnxruntime`。
* 长期记忆越攒越大时会一直喂给模型当前画像，所以画像本身限长 220 字，不会拖慢提示词。
* **"你走开了"靠的是全系统的键鼠空闲时间**（`GetLastInputInfo`），所以只要还有键盘鼠标在任何
  窗口上有动作，它就不会认为你走了；纯触屏、或者用遥控器/手柄看视频时，这个判断基本不会触发
  （也就不会来打扰你）。非 Windows 上这个能力自动退化：不判断走开/回来，其余照常。
* 它自己说的话（包括主动搭话）不会写进 `memory.json`，长期记忆里只记"它陪你看了什么"；
  和你的对话也不会写进去（免得闲聊把你的画像带歪），只保留在本次运行的面板里。
  你说话时当场算出的对话类型（记录 / 分析 / 学习）同理，只在内存和控制台里，不落盘。
* **情绪和对话类型都不上界面**：气泡里不画「好奇」那种小标签，聊天面板里也不写 `[开心] 台词`——
  它们只在内部用（切表情、气泡边框配色、这一轮怎么接话）。分类是本地关键词 + 情绪兜底，
  拿不准就归到「记录」（记下来最安全），刻意不做成"给你贴人格标签"那一套。
* **语音输入要系统支持**：走的是 Windows 自带识别引擎，需要装中文语音包
  （「设置 → 时间和语言 → 语音」里能加），麦克风权限在「隐私和安全性 → 麦克风 →
  允许桌面应用访问麦克风」。这台机器如果没装，`--selftest` 会直接告诉你，改用打字聊天即可。
  识别质量看环境安静程度（离线引擎，不上传音频）；识别完默认先填进输入框让你确认。
* **5W1H 靠模型配合**：提示词要求回两行（台词 + 场景），但小模型偶尔会忘，这时就只有台词、
  没有场景——不影响它说话，只是记忆里少一层线索。`--selftest` 会打印这次的场景，
  没给出来就说明格式没被遵守（可以把 `persona.max_chars` 调小、或换个更强的视觉模型）。
* **抠图效果看原图**：纯色背景（尤其白底）最干净；复杂/渐变背景需要手动 `--bg` + `--tol` 微调。
  生成的是"用一张静图做出动效"，不是手绘逐帧动画，所以不会有眨眼、口型这种局部动作。

## 接下来可以做的事

* ~~语音更自然~~：**这条路已经砍了**——语音播报（TTS）整个撤掉，它现在只用气泡说话。
  如果哪天真想让它开口，再单独接 `edge-tts` / GPT-SoVITS 之类就行。
* **让它说话不只靠画面**：接系统音量/进程名，判断"你在看剧还是在打游戏"，
  切换吐槽风格；或者接弹幕接口直接读弹幕流，而不是靠 OCR
* **形象再升级**：`tools/make_pet.py` 现在已经能把一张图抠出来 + 生成呼吸/弹跳/摇摆的循环帧；
  再往下可以做眨眼帧（在眼睛上盖一层肤色再切帧）、说话时的口型帧，或者直接接 Live2D。
  `assets/pet/` 的 `idle_* / talk_* / <情绪>_*` 命名规则都留好了
* **对话再自然一点**：现在对话是"一轮一问一答"，还可以做流式回答（边说边出字）、
  让它记住"上次聊到哪儿了"。**对话类型已经做了一半**（记录 / 分析 / 学习，见 ③）：
  下一步可以让这份分布也落盘，按"他最近问得多 / 情绪多"直接调搭话频率和话头，
  而不是只写进这一轮的提示词
* **多角色**：同一条流水线挂多个形象，各给不同人设（一个毒舌一个捧哏），
  在同一份记忆上下文里对话
* **主动搭话再进一步**：现在它只是"挑一个你最近老在看的东西"起头，还不能顺着聊——可以记住
  上次搭话聊到哪儿、你搭没搭理它（比如搭话后 30 秒内画面/键鼠有没有动静），把没被接住的话题
  收起来，下次换个说法；也可以按"你正在用什么软件、什么时候"换语气（打游戏时起哄、看网课时闭嘴）
* **长期记忆可视化**：一个小面板展示"它眼里的你"（画像 + 标签云 + 时间线），
  比直接读 JSON 直观
* ~~桌宠串门（跨电脑）~~：**局域网这一半已经做完了**（见 ⑧）——两台电脑各自开着挂件、
  交换一张名片（`pet_id` 认人 + 口令对暗号），就能让一只去对方屏幕上坐一会儿：
  出门口等主人点头、两只宠物各在自己那台机器上生成台词、谁都能随时喊它回家。
  走的是标准库 `http.server` 直连，**没有中转服务器**，所以只有这一句和形象的几张待机帧过网。
  还没做的是"跨公网开箱即用"：NAT 穿透 / 打洞 / 房间配对码那一套（现在得自己端口映射或者
  用 ZeroTier、Tailscale 把两边放进同一个虚拟局域网）。
  真要往下做，最该先想清楚的是**隐私与打扰**：谁都能把窗口开到你屏幕上，这事不能只靠好意——
  比如陌生人也能敲你的门（现在靠"得先把你的名片给对方"挡着）、一串好友同时来串门、
  以及"对方屏幕上会冒出你的宠物"这种社交压力，都该有更明确的产品约定。
* **好友系统再往前走**：现在客人只会说模型给的那几句话，还可以让它替对方带个口信、
  把"今天陪你看的这支视频"当见面礼（只传那句话，不传画面）、
  或者按"谁常来"排个座位（`friends.json` 里已经存着来过的人）。
  ~~串门时看看对方在干嘛~~：**已经做了**（见 ⑧ 的「好友在干嘛」）——边界也钉死了：
  出去的是对方**在自己那台机器上拼好的那一句话**，原始截图和窗口标题一个字都不过网。
  再往下可以做的：真给动作配上帧（`assets/pet/<动作名>_*.png`）、
  好几只客人同时在屏幕上时互相搭话（现在是一对一）、按"谁常来"排个座位。
