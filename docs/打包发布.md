# 打包发布（给维护者）

把源码变成"别人能下载的软件"这一整套怎么工作、踩过什么坑、发布前检查什么。
只是自己用的话看 `docs/下载安装.md` 就够。

## 一、一条命令

```bat
build.cmd                        :: 双击（内部就是下面这条）
python tools/build.py            :: 常规：dist\ScreenPet\ScreenPet.exe（一个文件夹）
python tools/build.py --zip      :: 再压成 dist\ScreenPet-<版本>.zip（发给别人就是这个）
python tools/build.py --onefile  :: 单文件 exe（启动慢 1~2 秒，胜在一个文件）
python tools/build.py --clean    :: 先清 build\ 和 dist\
```

打包机要装的东西：`pip install -r requirements-dev.txt`（= 运行时依赖 + PyInstaller）。
冒烟测试不需要它。

产物长这样：

```
dist/
├─ ScreenPet/
│  ├─ ScreenPet.exe          ← 双击这个
│  └─ _internal/             ← Python 运行时、PySide6、assets/pet、OCR 脚本……
├─ ScreenPet-0.8.0.zip       ← 发给别人的压缩包
└─ ScreenPet-Setup-0.8.0.exe ← 有 Inno Setup 时才生成
```

## 二、为什么要有 `pet/paths.py`

打包之后最容易出的事不是"跑不起来"，而是**"跑起来了但配置写不进去"**：

- exe 待的地方（`C:\Program Files\ScreenPet\`、或者解压后的只读目录）**不可写**；
- PyInstaller 单文件模式还会把资源解压到一个**临时目录**，程序一退就没了——
  往那儿写配置等于每次启动都忘光。

所以路径分两套，全部收在 `pet/paths.py` 一个文件里：

| 函数 | 干什么 |
| --- | --- |
| `user_dir()` | **要写的东西**（config / memory / taste / data / run.out）放这儿。源码跑 = 项目根目录；打包版 = `%APPDATA%\ScreenPet`；`PET_HOME` 非空时一律听它的 |
| `resource_dir()` | **只读素材**（assets、config.example.json、knowledge.example.json、winocr.ps1）放这儿。打包版 = `sys._MEIPASS` |
| `seed_config()` | 第一次运行照着 `config.example.json` 生成 `config.json` |
| `describe()` | 日志第一行那句"写：… 读：…"，排查"配置改了不生效"全靠它 |

> 「开局自带的一点常识」走的是另一条路（`pet/knowledge.py`）：随包发一份
> `knowledge.example.json`，**第一次运行时撒进用户自己的目录**，撒完落一个
> `.knowledge-seed.json` 标记，只撒一次。里面只有"谁都能听"的东西——上网补课学到的
> 通用知识点 + 一份话头账本；**用户画像、爱好标签、屏幕上看来的台词/接话语料一样都不带**，
> 那是每个用户各长各的（怎么挑的见 `tools/make_knowledge_seed.py`）。

其它模块一律通过 `cfg.config_path().parent` 推自己那份文件的位置
（`memory.path` / `taste.path` / `learn.path` / `study.ledger` 都这么来），
所以**只要 config.json 落对地方，其它全跟着走**——这也是当初没给每个模块单独写路径的原因。

> 老用户的配置在**项目根目录**，源码模式一点没变；只有打包版换到 `%APPDATA%`。
> 挪位置这件事只发生在"换一种跑法"的时候，不会偷偷把你的文件搬走。

## 三、打包时都带了什么

`tools/build.py` 里的 `BUNDLED` 就是清单（改了记得两边同步）：

| 源 | 打包后 | 为什么要 |
| --- | --- | --- |
| `assets/pet/` | `assets/pet/` | 形象帧（`PetRenderer` 按 `ASSETS_DIR/pet` 找） |
| `assets/source/` | **不带** | 画形象用的素材（3.6MB），运行时用不到 |
| `config.example.json` | 根目录 | 第一次运行拿它当模板 |
| `knowledge.example.json` | 根目录 | 开局自带的那点常识（见 `pet/knowledge.py`）：第一次运行撒进用户目录，只撒一次 |
| `pet/winocr.ps1` | `pet/` | Windows OCR 那层壳（`ocr.py` 用 `Path(__file__).parent` 找它） |
| `pet/asr.ps1` | `pet/` | 语音识别那层壳 |

另外两件小事也在这里做了：

- **图标**：`--icon assets/app.ico`；文件不存在就先调 `tools/make_icon.py`
  （形象是矢量画的，所以图标得先渲染一遍，再用 Pillow 打成一个多尺寸 ico）；
- **版本信息**：`build/version_info.txt` 由 `pet.__version__` 生成，
  顺手把 `installer/ScreenPet.iss` 里的版本号改写成同一个值——
  版本号只有一处真源（`pet/__init__.py`），别的地方都跟着走。

发车前还有一道**闸**（在 PyInstaller 之前跑）：

- **开局常识复核**：`knowledge.example.json` 是要发给新用户的，打包前先用
  `make_knowledge_seed.audit_seed()` 量一遍——平台名（`抖音算法推荐个性化内容` 这种）、
  照着屏幕说的话（`这集都第28集了`）、白名单外的话头（`暗区突围`「王者荣耀」= 作者的观看历史）
  都算"作者自己的东西"，**量出问题就不出包**。种子文件躺在仓库里、谁都能手改，这道闸就是替你
  把门；真要硬打：`python tools/build.py --allow-dirty-seed`（只给自己排查，别发出去）。

## 四、安装包（可选）

绿色版够用了；要"像正经软件一样装一次"就用 Inno Setup 6（jrsoftware.org）：

1. 先 `build.cmd`（脚本要读 `dist\ScreenPet\`）；
2. 用 Inno 打开 `installer/ScreenPet.iss` → 编译 → `dist\ScreenPet-Setup-<版本>.exe`。

几点设计取舍：

- `PrivilegesRequired=lowest`：默认装在用户目录、**不要管理员**（更少 UAC 折腾），
  向导里想装 Program Files 也能选；
- 卸载时**不删** `%APPDATA%\ScreenPet`：记忆和语料是用户的东西，重装还认得他；
- 中文安装界面要在 Inno 里装语言包，然后把 `.iss` 里那两行 `[Languages]` 的注释去掉。

## 五、自动发布（GitHub Actions）

`.github/workflows/build.yml`：**打个 tag 就自动出 Release**。

```bat
git tag v0.8.0
git push origin v0.8.0
```

流程：装依赖 → 跑冒烟测试（真跑一遍 82 项）→ 生成图标 → `build.py --zip` →
上传产物 → 建 Release 并把 zip 挂上去（Release 说明里已经写好了"怎么用"）。

也可以在 Actions 页面手动触发（workflow_dispatch），只出产物不发 Release。

> 冒烟测试会真截屏、真跑 OCR（模型走 mock，不联网），所以 CI 上跑没问题；
> 本机跑之前记得先把自己的挂件退掉（`restart.cmd --stop`），跑完再 `restart.cmd` 起回来。

## 六、发布前检查清单

- [ ] `python -m compileall -q pet tools main.py`
- [ ] `$env:QT_QPA_PLATFORM="offscreen"; python tools/smoke_test.py` —— 全绿（当前 82 项）
- [ ] `python main.py --selftest` —— 截屏 / OCR / 模型至少有一项通
- [ ] `python tools/build.py --clean --zip` —— 打出来能双击、托盘图标正常、右键菜单能开
- [ ] 用**干净环境**验一次（换台机器，或把 `%APPDATA%\ScreenPet` 改名假装第一次用）：
      应能看到"第一次用"的提示气泡、`%APPDATA%\ScreenPet\config.json` 被生成
- [ ] `pet/__init__.py` 的 `__version__` 提过了（`build.py` 会把它同步进安装脚本和 exe 属性）
- [ ] README 的"打包成软件"那一节和 `BUNDLED` 清单对得上

## 七、已知的坑

| 现象 | 原因 / 怎么办 |
| --- | --- |
| 双击没反应 | 先在命令行里跑 exe（`ScreenPet.exe --console` 可以留住控制台），看报错；日志也在 `%APPDATA%\ScreenPet\run.out` |
| SmartScreen 警告 | 没买代码签名证书，正常。介意就自己从源码打包，或让用户点"仍要运行" |
| 包特别大（150MB+） | PySide6 本身就大。想瘦：`--exclude-module` 继续裁（Qt 的 WebEngine / 3D 之类），但别裁 `PySide6.QtWidgets` |
| 杀毒误报 | PyInstaller 单文件 + 无签名容易中招。优先发 **onedir** 版（就是默认那个） |
| 某个功能找不到入口 | 没有热键：命令全在**右键菜单**里（挂件右键 → 陪你看 / 跟我说说话 / 我自己的事） |
| 用户说"改了配置没用" | 十有八九改的是 exe 旁边的文件。让他看日志第一行的"写：…"，照着改 |
| CI 上"asr 语音输入实测"红叉 | 云端 runner 没有麦克风。这一项在"这台机器没有录音设备 / 没装语音包"时会**跳过**而不是失败（`AsrError.environment`，见 `tools/smoke_test.py::test_asr_engine`）；本机有麦就跑真的那次听 |
